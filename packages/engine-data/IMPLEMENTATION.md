# flint:engine-data

Declare a struct with a Table name and exactly one integer Id field.
Fields map by their names unless a Column annotation supplies an alias.
Table and column names use ASCII identifiers, and column names must be
unique across case variants. ReadOnly fields participate in reads.
Nullable!T represents SQL NULL separately from zero, false, and empty
text or bytes.

Construct SqlRepository from an already open Pool. It copies the pool
handle and runs a zero-row query against the generated column list.
Apply migrations before constructing the repositories. A schema check
that cannot establish the mapping throws during startup.

Save with an ID of zero to have the database generate the ID. Save with
an existing nonzero ID to update. Use insert for a new explicit nonzero
ID and to get a conflict on a duplicate. A Version field makes the
generated update compare the previous version, increment on success,
and report a conflict for a stale write.

Each call uses one exclusive SQL lease. Row readers copy text and bytes
into the supplied request arena. A copy of the DTO still depends on that
arena's lifetime. The mapRow function maps one non-null cell at a time.
The repository's typed row consumer handles SQL NULL.

## Named queries

Annotate a parameter struct with one Query and pass it to
repository.queryOne!Projection with a caller-owned arena. Its fields name
the bound parameters. Column can supply a different parameter name.
Named parameters are replaced in first-reference order and repeated
references share one bound value. Quotes, identifiers, comments and
PostgreSQL dollar quotes retain their literal contents. The generated
query selects the explicitly mapped projection aliases. Supply an
explicit PostgreSQL cast in SQL when a nullable parameter has no
database type context.

## Verification

```sh
dub test :data --compiler=dmd
dub test :data --compiler=ldc2
python3 tools/gates.py --package data --gate structural
python3 packages/engine-data/fixtures/negative/verify.py artifacts/tasks/m3-data/negative
```

The native fixtures use the pinned SQL profile. Set
FLINT_DATA_PG_TEST_DSN to enable the disposable PostgreSQL fixture.
The 1-, 10- and 100-entity compiler fixtures are generated by
fixtures/scale/generate.py. The exercised benchmark and direct SQL
control both support SQLite by default and accept a PostgreSQL
connection string as a positional argument.
