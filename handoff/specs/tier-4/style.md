# flint:style — implementation specification

Catalogue tier 4. Research cut: 2026-11-21. This file specifies implementation work; declarations in contracts are type-checking interfaces, not runtime implementations.

## 1. Purpose and reference parity

Build predictable terminal text layouts using a small immutable style value, with display-cell accounting shared by all widgets.

- [ ] Foreground/background colors, bold/italic/underline, padding, margin and plain/rounded/double borders.
- [ ] Horizontal/vertical joins, alignment, explicit width and safe truncation.
- [ ] Display width accounts for combining marks, CJK and grapheme clusters.
- [ ] No global terminal state; rendering is a pure transformation from text/style/width to an owned string.

## 3. Public D contract

Canonical declaration module: [flint.style](../../contracts/source/flint/style.d). These exact signatures are compiled with DIP1000. Implement the declarations with the semantics below; do not put unresolved declaration stubs into production artifacts.

```d
module flint.style;
@safe:
struct Color
{
    ubyte red;
    ubyte green;
    ubyte blue;

enum Alignment : ubyte
{
    start,
    center,
    end
}

enum Border : ubyte
{
    none,
    plain,
    rounded,
    double_
}

struct Insets
{
    uint top;
    uint right;
    uint bottom;
    uint left;
}

struct Style
{
    Color foreground;
    Color background;
    Insets padding;
    Insets margin;
    Border border;
    Alignment horizontal;
    Alignment vertical;

{

    uint lines;

string joinHorizontal(scope const(char[])[] blocks, uint gap);
string joinVertical(scope const(char[])[] blocks, uint gap);
string truncateCells(scope const(char)[] utf8, uint maxCells, scope const(char)[] ellipsis = "…");
```

## 4. Internal architecture, ownership and safety

1. Separate measurement, layout and ANSI emission. ANSI control sequences generated by Flint have zero display width. All untrusted ESC, C0 and DEL input characters are replaced or escaped before layout; embedded terminal commands cannot reach the output.
2. Use pinned utf8proc for Unicode scalar properties and grapheme boundaries. Its Unicode data version is part of the snapshot fixture. Terminal width is a Flint policy: East Asian Ambiguous width 1, wide/fullwidth width 2, combining marks width 0, emoji grapheme clusters width 2. Real terminals can disagree; expose policy in future only through an explicit versioned API.
3. Do not iterate D string by decoded char accidentally. Decode explicitly, walk grapheme boundaries, and never truncate inside UTF-8 or a grapheme. A leading combining mark is rendered with a dotted-circle base and width 1.
4. render output is bounded by checked arithmetic and a 16MiB allocation limit; widths above 16384 are invalid at the internal validation boundary. Empty blocks and widths smaller than border/padding produce clipped output, not unsigned wraparound.
5. The native C Unicode shim stays in flint.style.ffi and does not pull in the TUI or terminal package. style is full D; utf8proc is not part of the tiny WASM package set. Return strings own their contents.
6. Prefer integer-cell layout arithmetic and static border tables. No regex, recursive template-generated layout tree, implicit global state, or module-wide Phobos import is permitted.

### Concrete implementation files

- `packages/style/source/flint/style/package.d`: public declarations, UDA definitions and entry points.
- `packages/style/source/flint/style/internal.d`: shared non-template state machines and checked arithmetic.
- `packages/style/tests/contract_tests.d`: behavioral tests identified in section 6.
- `packages/style/tests/fuzz/`: deterministic seed corpus and bounded fuzz entry points; no fuzz data downloaded at test time.
- `packages/style/source/flint/style/ffi/` and `sys/`: allowlisted native boundaries; every trusted function has an adjacent `// SAFETY:` proof and a matching ASan test.

The public surface defaults to `@safe`. Pointer arithmetic and native handle conversions are confined to those reviewed boundaries. This full-D package may allocate where documented. Do not add `@nogc` to an API unless every implementation path and callback has that contract.

## 5. Measured budget contract

**Per-package size definition:** the byte ceiling bounds framework overhead over an exercised baseline with the same direct Flint dependencies and the same selected native-provider workload. When a C/Rust provider is selected, the baseline performs that operation directly through the pinned upstream C ABI, without importing this Flint package; it must retain the same provider features and native work. An ABI-only adapter may be shared, but moving Flint validation, ownership or business logic into the baseline is prohibited. Adding an unused archive to a link line is not equivalent work. Preserve both complete stripped binary sizes and SHA256 values; the capped metric is `max(0, O3_feature - O3_baseline, Oz_feature - Oz_baseline)`. A valid zero delta is allowed. The full feature size remains visible and is not the wrapper delta. The fixed application caps count every retained native byte. Freeze both probe sources before establishing a baseline; no padding, unrelated feature retention or whole-archive tricks may inflate the reference. See the package's `bench/PROBE_CONTRACT.md` and the central producer protocol.

These are engineering ceilings, not measured performance claims. Use the fixed runner and sampling procedure in [CI performance budgets](../../docs/CI_PERFORMANCE_BUDGETS.md). Per-package timing excludes rebuilding dependencies; whole-application gates include the selected closure.

| Measurement | Ceiling |
| --- | --- |
| DMD cold / incremental package build | 0.35s / 0.35s |
| LDC cold / incremental package build | 2.10s / 1.05s |
| Incremental stripped linked bytes | 262144 bytes |
| Compiler peak RSS | 536870912 bytes |
| Template instantiations in the package fixture | 2000 |

Compile regression >10% or binary growth >5% fails independently of these hard ceilings. Native dependencies and final shared-library closure are reported separately and counted in the application deployment metric; they are never hidden by quoting only D wrapper size.

Required benchmark: Measure layout of 1KiB ASCII, 1KiB CJK and 1000 grapheme-rich rows. Record ns/cell, allocation bytes and native text/data contribution. Microbench the pure width scanner independently from string allocation.

## 6. Acceptance, edge cases and required tests

| Test ID | Stimulus | Required result |
| --- | --- | --- |
| STYLE-01 | ASCII, e + combining accent, CJK ideograph, family emoji | Cell widths and truncation match pinned fixtures; no broken scalar. |
| STYLE-02 | width=0, width=1, padding larger than width | Empty/clipped bounded output; no overflow. |
| STYLE-03 | Malformed UTF-8 and user ESC[2J | Replacement text is visible; no screen-clearing command survives. |
| STYLE-04 | Nested styles and horizontal blocks of unequal heights | ANSI state resets at each logical boundary; padding fills missing rows. |
| STYLE-05 | Empty joins and gap=0/4 | Deterministic no-trailing-newline layout. |
| STYLE-06 | Huge dimensions and arithmetic near uint.max | Controlled invalid input failure before allocation. |

The following is a real D test/usage fixture to place in the package tests. Runtime assertions become passing only after the specified implementation exists:

```d
import flint.style : measure, truncateCells;
unittest {
    assert(measure("A界").cells == 3);
    assert(measure("e\u0301").cells == 1);
    assert(truncateCells("abcdef", 4, "…") == "abc…");
}
```

For parser/codec boundaries fuzz every length from 0 through 256, then 1KiB/1MiB boundary seeds; reject overflows before allocation. Run a 60-second ASan smoke on every PR and a 30-minute corpus job nightly. A platform-specific test is required on the platform that owns the native boundary; a Linux compile-only job does not count as a Windows runtime pass.

From the implementation repository root:

```sh
dub test :style --compiler=dmd
dub test :style --compiler=ldc2
python3 tools/gates.py --package style --gate structural
```

Do not mark this package complete until behavioral fixtures, compile-fail safety fixtures, the package budget fixture and all applicable native/WASM jobs pass. A declaration-only typecheck is API verification, not a package acceptance result.
