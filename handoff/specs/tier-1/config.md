# flint:config — implementation specification

Status: normative design for agents; contract declarations have been syntax checked. Runtime behavior below is an acceptance requirement, not a claim that a framework implementation already exists. The compiler receipt is [core-contracts.json](../../verification/core-contracts.json).

## 1. Purpose and reference parity

Bind startup configuration into typed structs with deterministic precedence, profile selection, explicit diagnostics and secret handling.

- [ ] ConfigurationProperties-style prefixes; required/default/environment annotations; startup validation and fail-fast errors.
- [ ] JSON/TOML files, .env, process environment, profile overrides and command-line key/value overrides.
- [ ] No network configuration lookup, runtime polling, hidden hot reload or global mutable configuration singleton.

## 2. Package boundary and exact DUB recipe

Catalog tier: **1**. Direct allowed Flint dependencies: **flint:arena, flint:serde, flint:validate**. No transitive import is an excuse to add a direct import without updating the dependency policy. ## 4. Internal architecture, ownership and safety

Resolve the profile first: explicit `--flint.profile=NAME` overrides FLINT_PROFILE, which overrides ConfigOptions.profile. Accept only `[A-Za-z0-9_-]{1,32}` so profiles cannot traverse directories. `application.toml` and `application.json` are mutually exclusive base files; having both is an error. Load the same chosen format's `application-PROFILE` file when present. Missing base files are permitted only when every required field can be provided by another source or a default.

Precedence from lowest to highest is: D field initializer, `@Default`, base file, profile file, `.env`, process environment, command-line overrides. `.env` is parsed as data: one `KEY=VALUE` per line, optional matching quotes, backslash escapes only inside double quotes, no shell expansion or interpolation, UTF-8, no executable substitutions. Environment names are explicit via `@Env` or are generated by uppercase prefix plus double underscore between nesting levels, e.g. FLINT_SERVER__PORT. CLI overrides use `--set=server.port=8080`; split only on the first two equals delimiters and retain remaining equals in the value. Duplicate values within the same source are rejected; higher-priority sources override intentionally.

Bind structs recursively using a cached field descriptor per type. Coerce only documented scalar syntax: base-10 integers with checked range, lowercase true/false, finite decimal floats, UTF-8 strings and comma-separated CLI arrays with backslash escaping. File arrays use their format's arrays. No implicit int-to-bool or lossy numeric truncation. Required means present in a source/default, not merely nonzero. Reject unknown keys by default, including spelling mistakes. Preserve line/column and source in diagnostics, but never echo the value of `@Secret` fields. All errors are deterministic sorted by canonical key.

Configuration work is startup-only and may use GC-backed owned strings through `flint.serde.owned`. Run `validateConfig` after binding and before constructing services. Freeze the resulting config by convention as immutable startup state or copy it into per-core values. A watcher/reload feature is outside this release; adding one requires a separate versioned snapshot/ownership contract and cannot mutate values while requests run.

**Safety boundary:** All bind/validation/file orchestration public APIs are `@safe`; ordinary std.file/startup I/O is allowed only in internal native modules. This package is intentionally not BetterC and is never called from a request hot path.

## 5. Compile-time, size and runtime budgets

**Per-package size definition:** the byte ceiling bounds framework overhead over an exercised baseline with the same direct Flint dependencies and the same selected native-provider workload. When a C/Rust provider is selected, the baseline performs that operation directly through the pinned upstream C ABI, without importing this Flint package; it must retain the same provider features and native work. An ABI-only adapter may be shared, but moving Flint validation, ownership or business logic into the baseline is prohibited. Adding an unused archive to a link line is not equivalent work. Preserve both complete stripped binary sizes and SHA256 values; the capped metric is `max(0, O3_feature - O3_baseline, Oz_feature - Oz_baseline)`. A valid zero delta is allowed. The full feature size remains visible and is not the wrapper delta. The fixed application caps count every retained native byte. Freeze both probe sources before establishing a baseline; no padding, unrelated feature retention or whole-archive tricks may inflate the reference. See the package's `bench/PROBE_CONTRACT.md` and the central producer protocol.

These are release gates on the designated reference runner, not observed performance results. Measure the package's fixed feature fixture, with dependencies frozen; cold/incremental definitions and statistical regression rules come from [CI budgets](../../docs/CI_PERFORMANCE_BUDGETS.md).

| Metric | Hard ceiling |
| --- | ---: |
| DMD cold build | 0.80 s |
| DMD incremental build | 0.60 s |
| LDC cold build | 4.80 s |
| LDC incremental build | 2.40 s |
| Marginal stripped linked bytes | 262,144 bytes |
| Compiler peak RSS | 536,870,912 bytes |
| Template instantiations | 2,000 |

The >10% compile/template/RSS regression rule and >5% binary growth rule also apply; passing a hard ceiling does not permit silent drift. Marginal size follows the provider-equivalent definition above; full native-provider and dependency footprints remain in the recorded complete binaries. Package deltas are not summed to estimate an application. Native shared-library bytes and static-dependency bytes must both be reported. BetterC core: **not claimed**.

**Benchmark fixture:** Measure one 16-field and one 128-field startup bind, allocations and compile-time descriptor generation. Config import in a CLI must not pull reactor/web/sql packages into the build graph.

## 6. Required acceptance tests and edge cases

1. Every precedence pair, profile unknown/path traversal, both base formats present, UTF-8 BOM, .env quotes/escapes and empty values.
2. Required zero/false accepted when explicitly supplied; unsigned negative, integer overflow, NaN/Infinity and unexpected nesting rejected.
3. Secret diagnostics contain key/source but never sentinel secret bytes; recursive redaction verified.
4. Unknown field rejection, explicit ignore option, duplicate key at each source, duplicate --set override.
5. Typed config with 128 fields across 8 nesting levels passes; depth greater than 16 fails with a bounded diagnostic.

Every listed case becomes a named unittest or a compiler-negative fixture, with a deterministic seed for generated schedules/inputs. FFI/kernel lifetime tests run under the platform sanitizer jobs. Add regression fixtures for every corrected failure before closing the slice.

## 7. Agent implementation order and definition of done

1. Add the package modules and public declarations, compile the positive contract usage and the negative misuse fixtures, then implement the smallest deterministic behavior covered by the first acceptance group.
2. Complete ownership/error paths before adding throughput optimization; include bounded-resource exhaustion tests.
3. Add the fixed benchmark fixture, record raw samples and candidate baseline receipts, and complete all acceptance groups before activating this package for integration.

Run from `scaffold/` after implementing this package:

```bash
python3 tools/flint.py test --package config --compiler dmd
python3 tools/gates.py --package config --gate structural
```

The direct test equivalent is `dub test :config --compiler=dmd`. Repeat with `--compiler ldc2` through the orchestrator. A declaration-only contract pass is never a substitute for `dub test` on a runtime implementation. Full Gates 1–6 run for the integrated milestone once its canonical apps and runner baselines exist; absence of a required measurement blocks release rather than fabricating a zero measurement.
