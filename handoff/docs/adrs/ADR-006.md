# ADR-006: Separate request no-GC from process no-GC

Status: accepted design for the implementation handoff; date: 2026-11-21.

## Context

@nogc prevents GC operations in the annotated D call closure but another thread can trigger a process-wide collection. C malloc is also outside this property.

## Decision

Default profile keeps GC enabled. Strict profile creates service graphs before warm-up and prohibits later GC allocation on participating workers. Measure monotonic per-thread allocated bytes and global collection deltas around synchronized barriers; track native allocation/RSS separately. Arena payloads never hide GC pointers.

## Alternatives and consequences

GC.disable alone was rejected: it does not prove memory ownership, bounded memory or no explicit collections. addRange/removeRange are reserved for specifically reviewed foreign-root owners.

## Acceptance evidence

Inject an allocation on a request worker and another worker; both must invalidate strict-profile evidence. A collection-free allocating case must still fail allocation checks.
