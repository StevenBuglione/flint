# ADR-005: Pin fibers and normalize operations as completions

Status: accepted design for the implementation handoff; date: 2026-11-21.

## Context

kqueue readiness and IOCP completion have different buffer-lifetime rules. D fibers may technically be transferred while suspended, but TLS/request ownership would require additional migration machinery.

## Decision

One connection and fiber belongs to one reactor worker. Operation ID/generation is the portable identity; all buffers remain owned until final completion. Linux uses io_uring after probing and epoll fallback; macOS uses kqueue draining; Windows uses IOCP with stable OVERLAPPED storage. Task-local context is swapped at fiber switches.

## Alternatives and consequences

A universal readiness wrapper and arbitrary fiber migration were rejected. A bounded blocking pool is explicit for libraries lacking suitable async APIs. CPU affinity is observable best effort, not guaranteed real-time scheduling.

## Acceptance evidence

Test cancel/complete/reuse races on each real OS; stress interleaved request IDs; verify no double completion/free and deterministic shutdown.
