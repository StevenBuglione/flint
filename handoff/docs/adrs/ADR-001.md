# ADR-001: Pin two compilers and their common language subset

Status: accepted design for the implementation handoff; date: 2026-11-21.

## Context

The development/release split is useful only when application source behaves consistently under both compilers. LDC 1.43.0 reports D 2.113.0 frontend while DMD is 2.114.0.

## Decision

Pin DMD 2.114.0/LDC 1.43.0/DUB 1.43.0 and enable DIP1000. Shared code excludes frontend 2.114-only constructs. Exact official archive hashes are in policy/toolchains.json. Native development uses DMD Linux x86-64; release and other targets use LDC. Compiler output, target and libc enter every cache/evidence key.

## Alternatives and consequences

Do not use floating latest compilers or exchange DMD/LDC runtime objects. The cost is maintaining dual compile probes and explicit upgrades.

## Acceptance evidence

Compile every contract and golden app with both tools; compile negative lifetime fixtures expecting rejection; record versions.
