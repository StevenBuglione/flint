# ADR-011: Use empirical fail-closed performance evidence

Status: accepted design for the implementation handoff; date: 2026-11-21.

## Context

Compile-time budgets and Go superiority cannot be established from language choice. Shared cloud runners and unmatched loads can manufacture misleading results.

## Decision

Use fixed fingerprints, nine build/load samples per group, 21 micro samples, and deterministic 99% independent-sample bootstrap intervals for ratios of medians, hard caps and protected base-commit evidence. Compare exact workloads; zero errors; open-loop latency below common saturation; separate throughput sweep. Missing or inconclusive evidence blocks full certification.

## Alternatives and consequences

No synthetic initial baseline and no automatic cap increases. Initial implementation slices use package-specific correctness/structural gates; full six-gate certification is a later observed result.

## Acceptance evidence

Mutation-test metric thresholds, missing keys, NaN/zero samples, mismatched fingerprints, incomplete platforms and candidate-as-base; all must fail.
