# ADR-008: Split native D, BetterC core WASM and components

Status: accepted design for the implementation handoff; date: 2026-11-21.

## Context

A wasm32 triple does not supply GC, exceptions, WASI interfaces or component bindings. LDC release runtime support has target-specific limitations.

## Decision

Five cores use caller-owned storage/status returns and an import closure free of druntime-dependent features. Browser ABI is a little-endian checked command stream. WASI 0.2/0.3 require explicit WIT/Canonical ABI adapters and conformance. Native engine embedding is a separate optional profile.

## Alternatives and consequences

WASI 0.3 itself is published; only Flint component integration remains unimplemented until verified. Do not label a core wasm module a WASI component. Embedded Wasmtime size is excluded only from the unrelated browser-core profile, not from any native deployment size claim.

## Acceptance evidence

Build/link/run native BetterC and wasm probes; inspect imports; execute JS malformed-frame tests; run component conformance separately.
