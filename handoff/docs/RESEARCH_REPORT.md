# Research report: D foundations for Flint

Research cut: **2026-11-21**. Primary project documentation and source were consulted. Facts below are separate from Flint design choices and unmeasured performance goals. Exact executed checks are in `../verification/`; source URLs and lock evidence are in `../research/`.

## 1. Compiler reality and a common language baseline

DMD 2.114.0 was released on 2026-11-01. Its changelog includes language changes that LDC 1.43.0 cannot automatically be assumed to support. The downloaded LDC compiler reports frontend 2.113.0 and LLVM 22.1.8. Consequently Flint pins both compilers but restricts shared source to the overlap. New 2.114-only syntax, such as newly introduced tuple forms, is excluded until both toolchains pass a targeted probe. The compiler is never selected from an unpinned `latest` label. [DMD release](https://dlang.org/changelog/2.114.0.html); [LDC release](https://github.com/ldc-developers/ldc/releases/tag/v1.43.0).

DUB bundled with the downloaded DMD reports 1.43.0. DMD is the Linux x86-64 development compiler; LDC is the release and non-x86 compiler. Compiler identity, target, libc, flags and dependency lock are cache keys. DMD and LDC object/runtime files are not interchanged. A default `go` executable was not assumed to be the Go toolchain; the official Go 1.27.4 distribution was downloaded and its published checksum checked for the reference application. [Go releases](https://go.dev/doc/devel/release).

The ordinary development flags are `-g -w -de -preview=dip1000`. Unit test compilation adds `-unittest`; DUB's test command supplies its test runner. Release profiles use `-O3` or `-Oz`, `-release`, `-boundscheck=safeonly`, and `-flto=thin`. The verified native Linux path uses the system compiler driver and linker with LDC's bundled `LLVMgold-ldc.so` plugin; both O3 and Oz ThinLTO executables linked and ran in this handoff. An external matching LLD22 is an optional alternative, not a prerequisite. Bounds checks in `@safe` code remain enabled. A plain native link uses the platform compiler driver so CRT startup objects and system libraries are selected correctly. LDC's internal linker is used for freestanding WASM. The tested native `-link-internally` command failed to locate the CRT libraries, so native profiles retain the platform driver. [Observed native ThinLTO receipt](../verification/native-thinlto.json). [DMD flags](https://dlang.org/dmd-linux.html); [LDC compiler source](https://github.com/ldc-developers/ldc/tree/v1.43.0/driver).

LDC supports instrumentation-based PGO with `-fprofile-instr-generate`, a representative training run, `ldc-profdata merge`, and `-fprofile-instr-use=<merged.profdata>`. Profiles belong to an exact source/flags/workload combination. PGO is an additional release experiment, never a replacement for the ordinary O3/Oz gate or a selectively trained comparison against an unoptimized reference.

### Two requested flags needed correction

Actual LDC 1.43 rejects `-fsanitize=address,undefined` because `undefined` is not a supported LDC sanitizer value. D code is tested with `-fsanitize=address`; C shims use Clang `-fsanitize=address,undefined -fno-omit-frame-pointer`. This does not establish UBSan coverage of D semantics. Use the real D compiler's type/lifetime checks, assertions, fuzzing and ASan for that layer. A failed unsupported flag is not accepted as a skipped sanitizer job. [LDC sanitizer implementation](https://github.com/ldc-developers/ldc/blob/v1.43.0/driver/toobj.cpp); [Clang UBSan](https://clang.llvm.org/docs/UndefinedBehaviorSanitizer.html).

Actual dfmt 0.15.2 help does not expose `--check`. The supplied formatting wrapper formats to standard output and compares the bytes with the source, without changing it. It fails if a diff exists. D-Scanner 0.15.2 supports `--styleCheck`, `--imports`, `--ast`, configuration files and reports; its `--report` can return zero despite findings, so the quality runner checks findings as well as process success. [dfmt](https://github.com/dlang-community/dfmt); [D-Scanner](https://github.com/dlang-community/D-Scanner).

## 2. DUB workspace mechanics

Root `name "flint"` plus `targetType "none"` is a catalog. It does not recursively build or test every child. Each `subPackage "packages/arena"` points at a recipe whose name is `arena`; the externally visible name becomes `flint:arena`. Sibling recipes use `dependency "flint:arena" version="*"`. The pinned DUB rejects the shorthand `:arena` inside a subpackage recipe; it remains valid as a command-line selector from the root. A root-only `dub describe` can return JSON after warning that a child recipe is invalid, so validation must assert the requested `rootPackage` and its actual dependency set. From the root, `dub build :arena`, `dub test :arena`, and `dub describe :arena` target that subpackage. The orchestrator enumerates and topologically orders affected packages explicitly. [Subpackages](https://dub.pm/dub-reference/subpackages/); [Recipe reference](https://dub.pm/dub-guide/recipe/).

Each package has its own source/import directory. A shared omnibus source root is prohibited because it allows undeclared imports to compile accidentally. Ordinary implementation packages use `targetType "library"`. Selecting `sourceLibrary` would inject all sources into the consumer invocation; that can defeat the intended compilation boundary. Template bodies still must be available to consumers, so precompiled library objects alone do not erase template-instantiation cost. Keep a small public interface and a non-template implementation. [Build settings](https://dub.pm/dub-reference/build_settings/); [D interface files](https://dlang.org/dmd-linux.html#interface-files).

Configurations are selected on the targeted subpackage. `subConfiguration "flint:arena" "some-name"` applies to a dependency, not an unrelated sibling. CI verifies all emitted recipes with the actual pinned DUB, retains `dub describe` JSON, and uses no inferred global workspace behavior. Sources and native dependency downloads are prepared before timed measurements. Cold compilation removes project build products; incremental compilation changes a source file. A no-op invocation is recorded separately and is not called an incremental rebuild.

## 3. Existing D ecosystem audit

These are adoption decisions for Flint, not claims that competing projects are slow. No comparative runtime or compile-time result was measured for these projects during this handoff.

| Project | Verified scope | Flint decision and reason |
|---|---|---|
| [vibe-core](https://github.com/vibe-d/vibe-core) / [eventcore](https://github.com/vibe-d/eventcore) | Fiber tasks, task-local storage, streams, timers and an event-driver abstraction | Study event/completion lifecycle and task-local context. Do not make the full package a mandatory dependency: Flint needs a separately auditable no-GC surface and independent feature closure. Evaluate a vendored isolated backend only after license/ownership and workload probes. |
| [photon](https://github.com/DmitryOlshansky/photon) | Fiber scheduler integrating blocking-style calls through libc wrapper interposition | Reuse design lessons, not transparent interposition as the runtime contract. Explicit wrappers/offload keep cancellation, supported platforms and blocking boundaries inspectable. |
| [serverino](https://github.com/trikko/serverino) | Compact HTTP/HTTPS/WebSocket server and practical application examples | Use as an ergonomics and workload comparator. Flint's parser/transport/arena boundaries remain independently specified; do not infer HTTP/2 or identical platform semantics from a small HTTP example. |
| [mir-ion](https://github.com/libmir/mir-ion) | JSON, Ion and other format support; preallocated internals and a documented exception strategy | Study number conversion and parser testing. Keep Flint's BetterC status-return JSON core independent. Full-D optional format adapters must not pull unsupported runtime requirements into browser WASM. |
| [arsd](https://github.com/adamdruppe/arsd) | Broad mostly separable modules; current README explicitly targets OpenD and disclaims continued official-D compatibility | No floating master dependency or wholesale vendoring. Individual historical ideas require a pinned provenance/license audit and both-compiler tests before copying. |
| [silly](https://code.dlang.org/packages/silly) | Lightweight named unittest runner | Preserve named unittest ergonomics in flint:test; do not make an alternate runner part of production artifacts. Registry/source evidence determines any future adapter pin. |
| [hunt](https://github.com/huntlabs/hunt) | Core/event/network/logging framework family with object-oriented APIs | Reference Java-friendly API organization; build Flint's narrow contracts over pinned C libraries instead of importing a broad foundation with incompatible ownership assumptions. |
| [OpenD](https://github.com/opendlang/opend) | A separate compiler/language lineage with quick and optimizing backends | Do not fork the language for v1. Two official-D compilers already impose a compatibility budget. An OpenD experiment is a separate branch and is excluded from claims about DMD/LDC compatibility. |

The selected policy is clean Flint orchestration over established native protocols, selective study of D implementations, and no default fork. Reuse is approved per module only when it reduces total maintained surface without violating licenses, ownership or benchmark caps.

## 4. Compile-time costs and bounded code generation

UDAs store metadata; they do not discover types, intercept methods or create a container automatically. `__traits(getAttributes, T)`, selected members and explicit registrations supply the input to generation. Every registry is bounded: 128 beans per application module, 256 routes per router module, 128 fields per DTO, depth 64 for recursive JSON/schema validation, and 256 methods per generated client. Exceeding a bound produces a clear compile-time diagnostic and requires splitting modules. These are engineering limits, not alleged compiler maximums.

Avoid transitive umbrella imports, `std.regex` template expansion in core, repeated recursive `AliasSeq` sorting, a `static foreach` over every symbol reachable from a module, exponential combinations of handler/template parameters, and formatting large generated source strings repeatedly in CTFE. Use one metadata pass per explicit type, cache immutable descriptors at compile time, put common parsing/routing loops in non-template functions, and separate each controller's generated glue from the router assembly.

DMD provides `-vtemplates=list-instances`; both pinned compilers expose time tracing. During preparation LDC required an explicit `-ftime-trace-file` path for the probe to write its trace. CI retains the raw traces and defines a parser-versioned instantiation counter rather than claiming a nonexistent universal template-cap compiler flag. Compiler RSS, wall time and generated-source bytes are tracked independently. A simple import count is not a compile-time benchmark. [Compiler flags](https://dlang.org/dmd-linux.html#switch-vtemplates).

When code generation becomes expensive, generate checked `.d` source as a build artifact from a deterministic descriptor using a small host tool. The generator and input hash become dependency edges. Generated imports are forbidden; imports are explicit in the handwritten generator wrapper. Generated files run through the same architecture, safety and formatting checks. Do not scatter metaprogramming into business handlers to conceal the cost.

## 5. Safety, arenas and lifetime enforcement

`@safe` protects only operations the compiler can establish as safe; `@trusted` asserts a contract the author must prove. A public `@safe allocate()->ubyte[]` plus an independently callable arena reset is insufficient: a client may retain the slice across reset. Flint therefore exposes generation-checked handles, scoped callback views, bounds checks and a reset prohibition during an active borrow. DIP1000 negative compilation tests reject stack-backed or callback-borrow escapes. Structs carrying an arena view are not implicitly sendable between threads.

Arena payloads contain native bytes, scalar values and handles, never hidden references to GC-owned objects. Startup service graphs are rooted normally in full-D application state; request code may borrow them without allocating. A deliberate interop object containing GC references in foreign storage requires a separately reviewed root owner: register its exact live range with `GC.addRange`, keep the registration through every foreign access, and remove it before freeing/reusing storage. This is not the default request arena design. [GC interface](https://dlang.org/library/core/memory/gc.html); [D lifetime attributes](https://dlang.org/spec/function.html#scope-parameters).

The zero-GC gate uses barriers around all participating request threads, monotonic `GC.allocatedInCurrentThread()` deltas, and a process-level collection count delta. `--DRT-gcopt=profile:1` is supporting diagnostic evidence, not a precise per-endpoint allocator counter. An allocation may not trigger a collection; before/after live heap sizes can miss allocation and reclamation. Neither alone proves the required property. [Thread allocation counter](https://dlang.org/library/core/memory/gc.allocated_in_current_thread.html); [Collection counters](https://dlang.org/library/core/memory/gc.profile_stats.html).

## 6. Reactor and GC coexistence

Flint pins a fiber to its owning event-loop thread and stores request logging/security context in the fiber/task object. A thread-local current-task pointer is swapped on every yield/resume. A plain thread-local MDC string would be shared by interleaved fibers and leak request context. The D Fiber documentation permits transfer of a suspended fiber; pinning is Flint's ownership policy, not a claim that the language always forbids migration. [Fiber](https://dlang.org/library/core/thread/fiber/fiber.html).

Linux defaults to io_uring when feature probing succeeds and uses an explicit epoll fallback when kernels/seccomp disable it. kqueue is readiness-based: drain until EAGAIN, preserve partial progress and rearm correctly. IOCP is completion-based: the OVERLAPPED object and buffers remain valid until final completion even after cancellation. The portable contract models operation identity, completion and ownership rather than pretending every backend has identical readiness events. CPU affinity is a best-effort platform facility with observable status; macOS scheduling is not a hard real-time guarantee.

TLS, DNS, disk and client libraries may block or allocate internally. Use libcurl multi integration, libpq nonblocking APIs and a bounded offload pool for actual blocking calls; never make an arbitrary C library safe for the reactor by merely annotating its D declaration `@nogc`. Native allocations are tracked separately from GC allocations. Queue saturation must backpressure or reject work, not grow an unbounded queue.

The default mixed-memory profile keeps GC enabled and makes no promise of no GC pauses. The strict benchmark/server profile prohibits GC allocation on all relevant threads after warm-up; a background worker allocating GC memory can invalidate latency goals even if every request handler is `@nogc`. Global `GC.disable()` is not a substitute for ownership or a bound on retained memory. [No-GC functions](https://dlang.org/spec/function.html#nogc-functions).

## 7. BetterC and WebAssembly

The five dual-target public cores are arena, serde, validate, wasm-bridge and ui-signals. They use no class allocation, interfaces requiring druntime, associative arrays, runtime TypeInfo, exceptions, module constructors, GC or unsupported standard-library services. Dynamic array syntax may represent a borrowed pointer/length view; it does not imply an allocator. Use caller-provided arrays and capacities, status codes and `extern(C)` exported entry points. Full-D owned strings/YAML adapters reside outside the BetterC import closure. [BetterC](https://dlang.org/spec/betterc.html).

The browser build is `ldc2 -betterC -mtriple=wasm32-unknown-unknown-wasm -Oz -link-internally -L--no-entry ...`. Export named functions such as `flint_tick`, not an assumed `main`: LDC's WASM main mangling follows target conventions. The emitted module has a versioned binary command-buffer ABI, bounded pointers/lengths and a small JS decoder that recreates typed-array views after memory growth. DOM updates use textContent and allowlisted attributes; raw HTML and arbitrary shader/source evaluation are not part of the command ABI.

WASI 0.2/0.3 and the Component Model need WIT bindings and Canonical ABI handling; a wasm32 target triple does not implement them. WASI 0.3 itself was released in June 2026. LDC 1.43 adds WASI runtime support with documented single-thread/fiber limitations. Flint's BetterC component adapter is a distinct conformance workstream. Native Wasmtime/WAMR embedding is yet another profile, with engine-specific budgets and no expectation that an embedded runtime fits the minimal browser-module cap. [WASI 0.3](https://wasi.dev/releases/wasi-p3); [LDC release](https://github.com/ldc-developers/ldc/releases/tag/v1.43.0).

## 8. C ABI, licensing and static distribution

The pin matrix fixes exact versions and source identities. Small C shims expose opaque handles, fixed-width integers, byte spans, status values and explicit destroy functions. Variadic APIs, packed bitfields, platform-dependent enums and vendor macros stay behind the shim. D `extern(C)` bindings reproduce the shim, with C and D sizeof/alignof/offsetof fixtures on each target. ImportC consumes that normalized header as an optional validation path; cross-target preprocessing must use the target headers and defines. [ImportC](https://dlang.org/spec/importc.html).

Static musl builds use official LDC Alpine packages and matching target runtimes, then build every linked native dependency for the same target/libc. A glibc runtime plus `zig cc -target ...-musl` is not an ABI conversion. Linux static acceptance inspects ELF interpreter/NEEDED entries and runs the binary in an empty runtime image. macOS and Windows require their OS frameworks/runtime contracts; do not market them as fully libc-free static artifacts.

Permissive-source requirements include transitive components and optional features, not just the top-level repository license. Disable unneeded SASL/GSSAPI/plugin backends unless explicitly reviewed. SQLite is public-domain software; PostgreSQL has its own permissive license; Boost and Apache-with-LLVM-exception dependencies need their actual notices. WebKitGTK cannot be silently admitted under a permissive-only rule. No license conclusion in this document replaces checking the exact pinned files in the bill of materials.

## 9. Updated service protocols and non-goals

MCP is pinned to 2026-07-28, with an explicitly separate older compatibility mode. Its revised Streamable HTTP removes the old GET/session model and uses request-scoped response streams. Server/client code follows the pinned transport spec rather than copying 2025 initialize/session examples. Read the MCP package acceptance tests for version/header agreement, bounded framing, cancellation, auth and origin validation. [MCP transport](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/streamable-http).

Spring/Go names are ergonomic references, not binary-compatible APIs or full-framework feature parity promises. Every per-package checklist identifies the supported Flint behavior. There is no Java classpath, bean-name reflection registry, arbitrary SpEL interpreter, transparent JPA proxy model or runtime monkey-patching. A UDA is effective only at a documented generated call boundary; direct D method calls do not automatically acquire transaction, authorization or retry semantics.

## 10. What remains empirical

No full Flint runtime existed before this handoff, so no honest source can establish its cold-build speed, throughput, p99, RSS or deployment size. The budget scripts reject missing samples and preserve absolute caps. The first implementation milestones establish trustworthy measurements and may expose an infeasible combination of goals. If so, report which exact workload/feature/target failed and the measured trade-off. Do not erase a requirement or publish a synthetic win.
