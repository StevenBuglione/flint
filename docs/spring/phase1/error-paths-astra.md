# Flint’s 404 and validation-error tails

**The 404 is solvable within Spring semantics. The validation benchmark has a larger fairness problem: Java and Flint close the connection after each 400, while Go can reuse it.** Go also sends both bodies with `Content-Length` where Java sends chunked responses. These comparisons are valid under the registered `semantic` rule, but they measure different HTTP/1.1 workloads. Neither the 404 framing difference nor the 400 reconnect cost has been isolated well enough to assign it a share of p99.

| Error path | Certified B2 Flint / Go | What changed afterward |
|---|---|---|
| `GET /nope` | p99 681 / 113 µs, CPU 35.2 / 9.1 µs, throughput ratio 0.377 | Write-behind cut local CPU from 32.4 to 16.3 µs, p50 from 244 to 88 µs, and p99 from 966 to 431 µs while preserving chunked output. |
| Invalid `POST /petclinic/api/owners` | p99 491 / 123 µs, CPU 60.8 / 16.0 µs | B3 includes write-behind, Jackson and validator changes. Its certified Petclinic result in this checkout is for the owner **GET**. The error runs were queued separately. |

Java’s 404 p99 was 574 µs at B. That describes one Spring implementation. It sets no lower bound on Flint. Likewise, dividing the later local 431 µs by the earlier certified 113 µs gives a useful estimate of the remaining gap, but no certified post-fix ratio. ## What the client receives

**404.** With `Accept: */*`, Tomcat sends HTTP/1.1 status 404 with an empty reason phrase, `Content-Type: application/json`, `Transfer-Encoding: chunked`, and a persistent connection. The 88-byte body is compact, in this order, with no trailing newline. The timestamp is fresh UTC with exactly three millisecond digits, including `.000`.

```json
{"timestamp":"2026-11-24T12:34:56.000Z","status":404,"error":"Not Found","path":"/nope"}
```

Go preserves the four fields, their order, timestamp format, original path, media type and persistence. Its status line says `404 Not Found`. `json.Encoder.Encode` appends LF, making 89 bytes. The recorded Go response uses `Content-Length: 89` and one write. Java’s chunk boundaries and the number of socket writes are separate from its choice of chunked framing. [404 golden](../../../benchmarks/spring/suites/golden/gs-rest-service.json:390) · [Go encoder](../../../benchmarks/spring/go/gs-rest-service/main.go:45) · [Go timestamp and path](../../../benchmarks/spring/go/gs-rest-service/main.go:77) · [Wire observation](/home/olfa/flint-work/coordination/error-404-stall.md:53)

**Validation 400.** Tomcat sends status 400 with an empty reason phrase. These are all the headers retained by the golden, in recorded order. Go supplies the same three `Vary` values in the same order and all six security headers with the same values. `Date` is a server-generated HTTP date and the recorder discards it on both paths.

```http
Vary: Origin
Vary: Access-Control-Request-Method
Vary: Access-Control-Request-Headers
X-Content-Type-Options: nosniff
X-XSS-Protection: 0
Cache-Control: no-cache, no-store, max-age=0, must-revalidate
Pragma: no-cache
Expires: 0
X-Frame-Options: SAMEORIGIN
Content-Type: application/problem+json
Transfer-Encoding: chunked
Connection: close
```

Both bodies are compact JSON with no LF. Both use the following key order and values, with the actual request origin and current instant substituted. The harness reports 426 bytes as an example. Port length and timestamp precision affect the actual size.

```json
{"detail":"The request contains invalid or missing parameters","status":400,"title":"MethodArgumentNotValidException","type":"{origin}/petclinic/api/owners","timestamp":"2026-11-24T12:34:56.123456789Z","schemaValidationErrors":[{"message":"Field 'telephone' must match \"^[0-9]{10}$\" (rejected value: 01234abcde)","field":"telephone","defaultMessage":"must match \"^[0-9]{10}$\"","rejectedValue":"01234abcde"}]}
```

Go sends `400 Bad Request`. Its handler marshals once and writes the small body without flushing or requesting close. Standard `net/http` therefore supplies its actual `Content-Length` and permits reuse. Flint explicitly implements Tomcat’s close-on-400 rule. Go’s `RFC3339Nano` also trims individual trailing fractional zeros, whereas Java `Instant` uses groups of three digits (0, 3, 6 or 9). Some instants consequently differ byte-for-byte even at the same clock value. These Go 400 transport details follow from source. The available golden is a normalized Java record, so it cannot establish a byte-for-byte comparison of raw header casing, inter-name order, `Date` placement or chunk boundaries. [400 golden](../../../benchmarks/spring/suites/golden/petclinic-rest.json:3583) · [Go body, clock and writer](../../../benchmarks/spring/go/petclinic-rest/web.go:155) · [Flint persistence decision](../../../packages/engine-web/source/flint/engine/web/runtime.d:1213)

**What a pass establishes.** Both modes lowercase header names, ignore order between distinct names, preserve repeated-value order, discard `Date`, substitute the origin, and read a dechunked body. `exact` additionally checks reason, framing headers, JSON key order and compactness. `semantic` waives all four, including compactness despite the README’s shorter description. Its ignored headers are `Content-Length`, `Transfer-Encoding`, `Connection` and `Keep-Alive`. Even `exact` accepts 1–9 fractional digits for the validation instant. Under load, separate correctness probes validate JSON, status and media type. The timed stream checks status counts, transport errors and aggregate body size. The probes themselves request `Connection: close`, so they cannot expose the reuse advantage. ## Where Flint spends the time

**404.** The original profile counted 209.4k instructions and 73 allocations. The first dispatch cost 47k instructions. The default `/**` resource handler in this port has no configured resources and performs **zero filesystem or classpath probes** for `/nope`. Today it constructs `NoResourceFoundException` and, for the exact stock handler and adapter, passes it directly to MVC’s resolvers. The historical 17.5k-instruction unwind has already been removed. The default resolver calls `sendError`. The servlet engine sets `jakarta.servlet.error.*`, switches to `DispatcherType.ERROR`, and runs the error filter chain and dispatcher on `/error`. That second pass originally cost 98.5k instructions, including lookup, HTML-versus-JSON negotiation, Boot’s ordered error-attributes map, and Jackson serialization. The two lookups together cost 41k. These are overlapping historical instruction counts. [Callgrind attribution](/home/olfa/flint-work/coordination/error-404-profile.md:22) · [Resource handler](../../../framework/webmvc/source/flint/web/servlet/resource.d:77) · [Error dispatch](../../../framework/engine-servlet/source/flint/engine/servlet/package.d:529) · [Boot controller](../../../boot/module/flint-boot-webmvc/source/flint/boot/webmvc/autoconfigure/error.d:155)

**400.** This path binds the owner DTO, validates it, produces a `BindingResult`, and delivers `MethodArgumentNotValidException` to Petclinic’s **application advice**. The advice reads the field errors and constructs the response. Boot’s `/error` controller is bypassed. Go also decodes the actual input and checks all five owner fields, including the telephone pattern. The SQL census records zero statements for all three implementations. Flint has already cached constraint metadata, made exception messages lazy, and streamed `ProblemDetail` through one Jackson generator. Historical local measurements put validation at 285k→46k instructions and the converter at 72k→39k. A later whole-request profile still counted 387k instructions and 217 allocations. [MVC validation](../../../framework/webmvc/source/flint/web/servlet/mvc/method/annotation.d:594) · [Application advice](../../../benchmarks/spring/flint/petclinic-rest/src/org/springframework/samples/petclinic/rest/advice/package.d:82) · [Go constraints](../../../benchmarks/spring/go/petclinic-rest/validate.go:324) · [SQL census](../../../benchmarks/spring/evidence/sql-census/petclinic-rest-20261124T0437Z/table.md:43) · [Profile history](../../../docs/spring/performance-playbook.md:50)

**The remaining p99 has no demonstrated single cause.** Before write-behind, other connections’ sends intervened between head, chunk and terminator. About 70% of the traced server span was spent parked after dispatch. That trace found 173 ms of GC in 18 seconds, with its clearest effect at p99.9 and above. After coalescing, an 88-byte body needs only 11 additional chunk-syntax bytes for one chunk and its terminator. That is a weak explanation for hundreds of microseconds. Stronger candidates are ready-queue delay across two reactors, pauses and the backlog after them with 46–59 allocations per 404 on 1 MiB pools, and client scheduling delay included by open-loop latency correction. The 400 additionally pays reconnect, accept and teardown. Mean server CPU and client p99 cannot apportion these costs. ## Fairness verdict

**Keep both B2 failures on record. Adopt a reviewed HTTP parity ADR for the gated error workloads, preserve Java’s golden, and retain idiomatic Go as a separately labelled comparison.** The registered rule deliberately permits Go’s framing, so B2 was scored correctly. It cannot support a claim of equal client-observable work, especially when one validation request consumes a TCP connection on only one side. ADR-032 supplies the precedent: match the externally visible operation while allowing each implementation to execute it efficiently. Require matching body format, framing and connection lifetime on the gated paths. Allow write coalescing and independent internal dispatch. The 404’s substantial CPU gap remains Flint’s to close, and beating Go at p99 remains an empirical target. ## Ranked actions

1. **Proof-harness and web-http — establish the transport cost.** In the next authorized window, capture raw HTTP/1.1 responses and attempt a second request on each socket. Compare Go’s current behavior, chunked with reuse, and chunked with close on the 400. Count accepts per completed request. Expect roughly one reconnect per 400 under parity and little 404 cost from chunk bytes alone. Register the approved comparator and remeasure both sides and all affected evidence at one commit.
2. **Web-http and data-access — locate the post-fix tail.** At the fixed 10k/5k rates, join sampled client scheduled-send, actual-send and last-byte times to server read, ready, dispatch, write-submit and completion times, reactor queue depth, and GC pauses. Compare slow requests with their neighbors and with `/greeting`. Use separate diagnostic runs for tracing, then uninstrumented interleaved A/Bs. Optimize the span that moves p99.
3. **Flint-AOT, web-http and Boot — specialize the default JSON 404.** Prove at startup that both mappings, resource handling, REQUEST/ERROR filters, interceptors, resolvers, error page/controller/attributes, inclusion options and converter match the stock path. Guard method, path, query and `Accept` per request. Emit the current timestamp and escaped original path through the configured serialization rules. Fall back before side effects for customization, HTML, uncertain matches or mutable configuration. This targets most of the historical 98.5k-instruction second pass and its temporary map. Test custom hooks and their invocation order with specialization on and off. [Existing proof model](../../../docs/spring/phase1/fast-path.md:39) · [Error-attribute construction](../../../boot/module/flint-boot-webmvc/source/flint/boot/webmvc/error.d:59)
4. **Web-http, third-party-apis and Flint-AOT — optimize validation through the real advice.** Bind and validate once, carry the typed failure and binding result directly to the selected resolver where proven equivalent, and invoke the advice once. Profile remaining violation construction, DTO access, serialization and connection teardown. Expect to save an unwind, avoid duplicate validation in the proposed fast path, and reduce temporary allocations. Preserve custom validators, messages, security/CORS and all returned fields. Certify both paths in nine interleaved trials against **≤0.99×** the approved Go p99. At the old denominators that means approximately **112 µs for 404 and 122 µs for 400**.
