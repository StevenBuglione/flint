# A structural performance lead for ordinary Flint applications

**There is no silver bullet that makes every Spring-style application beat Go on every metric.** The closest thing is already working in Flint: generate the shortest path that preserves what the application can observe, prove at startup that the configured beans permit it, and keep the ordinary Spring path available at the exact point the proof ends. On `/greeting`, enabling the existing fast path produced **1.394× throughput, 0.659× CPU/request and 0.507× p99** against the same Flint binary configuration with it off. Peak RSS was **0.999×**. That last number matters as much as the first three. A better request path can win CPU and latency while doing almost nothing for resident memory. [Fast-path A/B and implementation](../../../docs/spring/phase1/fast-path.md)

I would extend this mechanism across MVC, codecs and JDBC, keep fibers as the default execution model, and spend the next PetClinic measurement window on the database. The two applications have different ceilings.

## Mechanisms, ranked by expected return

### 1. Specialize framework decisions once, then reuse the existing engines

`flint build` already enables `AotRequest.fastPath` by default. The fork extracts typed declarations. `fastShape` selects a narrow mapping, `emit.d` emits its invoker, and `plan.d` adds Boot’s configurer and servlet offer only when an eligible endpoint exists. At startup, MVC checks the **actual** resolver, converter, handler and negotiation order. At request time it checks the concrete path, headers and buffer bounds. That division lets a deploy-time profile or custom mapper change behavior correctly. It also explains why all 37 PetClinic mappings currently fall back. [Generator](../../../apps/flint/src/flint_tool/engine/aot/fast.d) · [MVC startup proof](../../../framework/webmvc/source/flint/web/servlet/mvc/method/fast.d) · [Servlet offer](../../../framework/engine-servlet/source/flint/engine/servlet/fast.d)

Extend it first to single-pass parameter binding, cached Jackson property writers, integer path variables and `ResponseEntity`. Share escaping, converters and framing with the generic implementation. Precompute literal field names, static header fragments and validation metadata. Evaluate IDs, timestamps, locale, validation groups, paths, authorization decisions and custom getters when the request requires them. A configured filter can observe a request, mutate a response, audit a denial or throw. Skip it only when the framework proves its absence or reproduces its complete observable effect. The same design carries to Thymeleaf’s literal template spans, JPA’s mapping metadata and Kafka’s schema writers. Lazy loads, contextual escaping and delivery acknowledgements remain real work.

**Fallback has a commit point.** Before any observable action, decline to Spring. After a controller, validator with side effects, or interceptor has run, continue with the existing result or exception and materialize the objects the next extension needs. Never invoke the controller twice. After response commitment, preserve the transport’s existing failure behavior. A concrete regression test is `/greeting` with an unacceptable `Accept` header: the 406 still consumes an ID. [Fast-path contract](../../../framework/engine-aot/source/flint/engine/aot/fast.d) · [Greeting comparator](../../../benchmarks/spring/go/gs-rest-service/main.go)

**One-day test.** Implement one shared Jackson property writer or the planned single-pass binder. The old greeting profile attributes about **4k of 43.2k instructions** to per-property dispatch and **2k** to binding. A **3–8% CPU reduction** and **0–8% capacity gain** are reasonable hypotheses for one slice. Expect at most a few microseconds at p50, uncertain p99 and roughly flat RSS. Exercise repeated and escaped parameters, HEAD, 406, a throwing getter and a custom converter on both paths. For PetClinic, the existing **8–15% capacity** projection for expanded MVC shapes is worth retesting *after* lease repair. For 404 and validation errors, measure those routes independently. Their advice and error-body costs differ. One erased writer and small tables should cost little cold-build time or Oz size. Measure both before adding per-endpoint code. [Instruction breakdown and shape plan](../../../docs/spring/phase1/fast-path.md)

### 2. Specialize the JDBC work and preserve the transaction

Have AOT describe constant SQL, bind order and expected row shape. At startup, JDBC can select an immutable binding and row-conversion plan for a known driver and mapper. Validate the actual result metadata before using ordinal access. Keep prepared handles bounded and scoped to the physical connection and its session state. `engine-sql` already exposes a per-connection statement-cache limit and its libpq wrapper has prepared and parameterized paths. Measure which path actually runs before adding a cache. Dynamic SQL, changed metadata and custom row mappers use ordinary JDBC. Generated transaction glue can bind the resolved advisor and manager once. Propagation, self-invocation, rollback rules, synchronization callbacks and commit failure still follow the existing proxy and transaction manager. [SQL engine](../../../packages/engine-sql/source/flint/engine/sql/package.d) · [libpq wrapper](../../../packages/engine-sql/native/ffi/flint_sql_pg.c) · [Transaction interceptor](../../../framework/tx/source/flint/transaction/interceptor/package.d)

**Pipelining has a narrower use.** libpq can send already-known commands before reading earlier results. PostgreSQL executes them in order. A failed command can abort subsequent commands through the next synchronization point. Owner 1 first loads the owner, translates a missing row into an exception, then obtains the pets query parameter from that object. Its extractor can fail before the types lookup. An explicit JDBC batch with known inputs is a good first candidate. Speculatively combining arbitrary requests would couple leases, cancellation, errors and transaction state. Holding a request to form a batch also spends p50 and p99 budget at low load. [Owner repository](../../../benchmarks/spring/flint/petclinic-rest/src/org/springframework/samples/petclinic/repository/jdbc/package.d:93) · [PostgreSQL pipeline semantics](https://www.postgresql.org/docs/current/libpq-pipeline-mode.html)

**One-day test.** Run the owner-1 concurrency ladder on both implementations. Count opens, prepare/execute/close operations, transaction commands, rows, copies and backend CPU per success. Compare one warm prepared path with the present driver. For a genuinely independent batch, inject a middle-command failure and cancellation, drain to sync, and reuse the connection. Each eliminated serial exchange can save up to its measured wait in lease hold. It buys little backend CPU if PostgreSQL still does the same work. The first material target is **104 to below 54 µs backend CPU**, then **100 to below 54 µs application CPU** under comparable load. Expect shorter lease queues to help both percentiles. Bound RSS by cached statements × connections, and share binding code to keep cold, edit and Oz cost near zero outside JDBC apps.

### 3. Bypass fiber admission only for bounded, proven handlers

The current servlet fast path still runs **inside a fiber**. `engine-web` posts the handler, and the reactor’s `FiberLocal` uses thread-local fallback storage outside a task. A direct call from the owner loop therefore needs an isolated logical request context, preserved admission limits and a fairness budget. The compiler fork would have to summarize transitive suspension, blocking, allocation and bounded work across the resolved call graph. `@nogc` proves none of the other three. Unknown delegates, foreign calls, custom hooks and unbounded loops take the ordinary fiber route from entry. Known blocking native operations use bounded offload. Transport backpressure needs an owned pending write through final completion. Discovering a wait halfway through an arbitrary D stack is too late to restart safely. [HTTP admission](../../../packages/engine-web/source/flint/engine/web/runtime.d:992) · [Fiber-local implementation](../../../packages/engine-reactor/source/flint/engine/reactor/package.d:128)

**One-day test.** Compare an owner-local fiber enqueue with a direct diagnostic handler, using the same admission limit, response bytes, slow readers and concurrent ordinary handlers. Count handoffs, runnable delay, touched stack pages and event-loop lag. A **0.5 µs** saving would be about **6%** of greeting’s scored CPU. Require a fixed-rate p50 improvement and no p99 starvation before investing in compiler inference. RSS savings depend on touched pages, not the 256 KiB virtual stack reservation. A blocked or CPU-heavy neighbor can erase the entire gain.

For waiting requests, prototype a stackless continuation only inside **one framework-owned operation** with known suspension points. A frame must retain GC roots, logical context, exception and `finally` state, cancellation generation and native ownership until completion. Compare it with the same operation on a fiber at 64 connections and at high parked concurrency. The plausible prize is fewer resident stack pages at high concurrency. At 64 connections, budget **zero throughput or percentile improvement** until measured. Per-handler state machines add cold compile time, edit invalidations and `.text`. Keep ordinary blocking-style user code on fibers. A production bypass would also require an amendment to ADR-030’s every-handler-on-a-fiber rule. [Execution and memory contract](../../../docs/adr/ADR-030-flint-is-a-spring-port.md)

### 4. Eliminate unobservable allocations and address RSS directly

ADR-030 keeps user-visible DTOs, entities, strings and collections GC-owned. Escape evidence can eliminate an unobservable box, keep private scratch on the stack, or let a writer consume a value directly. Passing a request-region object to a user callback violates the current contract. Copy-on-escape cannot generally preserve aliases, identity, retained C pointers or destruction order. Use an owned allocation before any uncertain escape. For engine buffers, retain ownership through the last kernel or C completion, including cancellation.

**One-day test.** Census live pages and allocation sites on the default fast path, then repeat the pool-size A/B. An earlier small-pool arm saved **4.4 MB** and lost **2.1% throughput**. Greeting’s current RSS gap is **5.7 MB**. Measure touched pages, GC frequency, CPU, p50 and p99 together before choosing a Boot default. Check escaping DTOs retained in a singleton and callbacks after cancellation. Pool policy costs essentially no edit time or generated code. A new collector carries substantially more risk, and the concurrent prototype already lost throughput and p99 locally. [GC measurements](../../../docs/spring/phase1/gc.md) · [Certified pool A/B](../../../docs/spring/phase1/decisions.md)

## The D advantage and its build budget

Go already performs escape analysis. Its comparator registers concrete handlers directly. Spring AOT and GraalVM already generate code for a closed world. Flint’s advantage is control over the entire path: D’s CTFE and static introspection can extract typed metadata once, value types and `scope` can remove private temporary objects, and `@safe nothrow @nogc` can enforce properties of shared engine code. The fork can supply semantic facts to the generator, and control of druntime lets Flint measure roots, stacks and pool residency. These capabilities can make a fast ordinary Spring application reproducible without application tuning. They confer no intrinsic advantage over the kernel or PostgreSQL. [Go allocation model](https://go.dev/doc/gc-guide) · [Spring native-image model](https://docs.spring.io/spring-boot/reference/packaging/native-image/introducing-graalvm-native-images.html) · [Flint performance playbook](../../../docs/spring/performance-playbook.md)

**The critical compiler trap is invalidation.** Today `iface.d` deliberately omits most method bodies. A body-only edit that introduces a blocking call must invalidate every dependent no-block proof even if zero signatures change. Keep ordinary descriptor keys as they are. Separately key inferred effects by body, resolved callees, target, compiler and flags, and propagate changes until summaries stabilize. Missing or stale facts select the generic path. Test an edit that adds a wait behind a helper and compare the incremental artifact with a clean build. Emit plain D per changed module, intern identical plans, and link shared erased engines. Keep templates thin and optional providers reachable only from their generated registration. [Interface keys](../../../apps/flint/src/flint_tool/engine/aot/iface.d) · [Build and size rules](../../../docs/spring/performance-playbook.md)

PetClinic at B passes platform-primed cold **0.261× Go**, shared dev edit **0.645×**, and stripped Oz **0.948×**. It fails scratch **1.417×** and static edit **2.53×**. Oz has only **593 KB** of absolute headroom to parity. Scratch spends **4.95 of 5.74 s** building the platform. m7 found **3,463 archive mentions for 67 archives** and locally cut a byte-identical link from **318 to 128 ms**. Keep deduplication, per-module static replay and separate scratch-platform work. Charge every new specialization its generated lines, template instances, cold/edit time and linked bytes. A fresh platform-only cache against stdlib-primed Go and a true scratch build against `go build -a` answer different questions. Both gates stand. ## Programme

1. **Unblock PetClinic.** Keep the reserved cross-thread wake, generation check and FIFO lease handoff. Run the owner-1 SQL attribution alongside them. This replaces millisecond polling and determines which SQL CPU cut deserves the next trial.
2. **Extend the existing default fast path.** Land single-pass binding, then one shared writer or row plan at a time. Add security, errors and `ResponseEntity` only with differential fixtures covering both the fast path and fallback. This replaces repeated framework work while preserving extension points.
3. **Run build and RSS work in parallel.** Keep m7’s link deduplication and static replay. Run the pool A/B on the default fast path. These directly address losses that handler generation cannot recover.
4. **Make fiber bypass earn its compiler work.** Run the bounded direct-handler experiment after owner-local admission is measured. Pursue a compiler proof only if it buys a repeatable fixed-rate win. Defer general state-machine lowering and user-visible regions.

Certify each candidate in the existing quiet queue with nine interleaved trials, unchanged workloads, byte-level acceptance and exact receipts. Keep the **1.30 lower throughput bound** and **0.99 upper bounds for CPU, p50, p99 and RSS** visible alongside every build and size gate. The CPU floors and proposed gains above are design estimates.
