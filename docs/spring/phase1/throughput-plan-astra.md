# Flint throughput plan and busy-wait audit

**PetClinic’s next change should be a measured FIFO lease handoff.** The PostgreSQL socket spin is established. The lease convoy is a strong hypothesis with a specific test. The most important design finding is that **a cross-thread wake cannot safely be implemented as an ordinary posted task**. The reactor stops dequeuing that mailbox when every fiber slot is occupied. That is exactly the state in which a resource release must be able to wake a waiter. [SQL lease wait](packages/engine-sql/source/flint/engine/sql/sys/wait.d:88) · [Reactor mailbox dispatch](packages/engine-reactor/source/flint/engine/reactor/package.d:1483)

**For gs-rest, start with the measured cost of binding and writing `/greeting?name=Flint`.** The certified fast-path arm reached **1.293× throughput**, with a 99% interval of **1.285–1.299**. Its p50 was **1.016×**, CPU/request **0.843×** with an upper bound of **1.061**, p99 **0.729×** with an upper bound of **0.934**, and RSS **1.450×**. Of those five, throughput clears the release floor and p99 clears its ceiling. Throughput still misses the requested 1.30× target. B’s ongoing run is the baseline for choosing the next gs-rest experiment. [Certified results](docs/spring/phase1/decisions.md:503)

I inspected checkout `b9357220`. It contains the original SQL wait. The Fix 1 timings below are the owners’ **local** results. This review used only lightweight reads. I made no file or coordination-state changes and ran no builds, tests, profilers, or benchmarks.

## Cross-thread wake design

1. **Capture the destination when registering.** Use an engine-internal handle containing a lifetime-managed runtime identity, owner, slot, task generation and **wait generation**. Today’s `TaskWaker` identifies a task lifetime. A delayed wake from wait A must also be rejected after the same task starts wait B. A releasing foreign thread cannot obtain the destination from `Reactor.current()`. Preserve the existing owner-local fast path. [Current wake contract](packages/engine-reactor/source/flint/engine/reactor/package.d:546)
2. **Make publication and parking race-safe.** Register the FIFO ticket and wake handle under the pool’s synchronization, then recheck eligibility and the epoch before parking. Release publishes the resource or reservation first, then signals the eligible waiter outside the pool lock. Give each registration a durable signalled state. A release before the fiber actually yields must prevent or immediately end that park. Cancellation, timeout, successful acquisition with more idle slots, withdrawal, pool close and **asynchronous native retirement** must all advance or notify the right waiter. Retirement currently clears `retiring` without a queue notification. Preserve the off-reactor wait-on-address path and FIFO order across both kinds of waiter. [Queue transitions](packages/engine-sql/source/flint/engine/sql/package.d:423) · [Native retirement](packages/engine-sql/native/ffi/flint_sql_core.c:206)
3. **Give control messages guaranteed space and service.** A bounded per-slot pending record plus a ready bitmap is one implementable design. Validate the registration before publishing; a stale producer must never overwrite a newer registration. Coalesce duplicates. A foreign producer release-publishes the record and rings the owner’s nonblocking `eventfd` on the unnotified→notified transition. The owner drains the fd and pending records, clears the notification state, then acquire-rechecks before blocking. Retry `EINTR`; a saturated eventfd already signals readability. Bound work per turn and keep the owner runnable while entries remain. Only the owner marks a task runnable or resumes it.
4. **Integrate with both Linux backends and teardown.** Reserve an internal control descriptor/token independent of public watch capacity. Epoll can monitor it persistently; io_uring can keep an owner-submitted poll outstanding, drain and rearm it. An event arriving during rearm remains readable. Keep the five-millisecond loop bound until stop, accept-stop, cancellation and deadline paths have equivalent wake coverage. On shutdown, stop admission, invalidate registrations, wake parked tasks, quiesce notifier writers, and retire poll/cancel completions before closing the fd or recycling the owner. Use a kqueue event/pipe and a reserved IOCP control packet for supported non-Linux targets. Windows native-socket polling at `package.d:1356` is a separate remaining fallback. [Loop and backends](packages/engine-reactor/source/flint/engine/reactor/package.d:1296)
5. **Prove progress under adverse ordering.** Extend `engine-reactor/tests/wake.d` with signal-before-park, signal-during-drain/rearm, duplicate signal, stale wait on a live task, recycled task/runtime, saturated ordinary mailbox, zero free fibers, timeout versus release, and stop during signal. Exercise forced epoll and io_uring with two owners. Extend SQL saturation tests with mixed fiber/thread waiters and multiple simultaneous free leases. Count completed handoffs, doorbell writes, owner resumes, queue delay and idle CPU. Common same-owner release should need **zero** notification syscalls; a burst to one sleeping owner should normally need one write and one drain. [Existing wake tests](packages/engine-reactor/tests/wake.d) · [SQL saturation contract](packages/engine-sql/ACCEPTANCE.md:15)
