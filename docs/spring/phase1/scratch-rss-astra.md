# Phase 1 diagnosis — PetClinic scratch build and greeting-service peak RSS

**PetClinic has a concrete build fix to test.** Two packages in its dependency graph disqualify the entire build from DUB’s parallel pipeline. **The RSS result points to a different fix.** Flint starts below Go after warm-up, then gains about 8 MB during fixed-rate traffic. The first experiment should capture that growth as it happens and test whether smaller GC pools prevent it. Neither proposed improvement is a certified win. This review used existing source and evidence only.

## 1. PetClinic scratch build

At baseline `ca5fbd4a46ed`, Flint took **5,744 ms** against Go’s **4,053 ms**, a ratio of **1.417** with a 99% interval of **1.409–1.448**. The receipt reports these independent phase medians. [Certified build results](../../../benchmarks/spring/evidence/phase1-builds-petclinic/20261124T023031Z/builds.json)

| Wall time | What B establishes |
|---|---|
| 71 ms | Flint CLI work outside the named build phases |
| 171 ms | AOT generation, including native DMD model extraction. All nine scratch logs show 15 models extracted and 42 loaded from the shared cache. |
| 4,953 ms | Residual DUB time. It includes dependency planning, recursive package compilation, native package work, archiving and project compilation. |
| 536 ms | Timed linker invocation |
| 5,738 ms | Internal total. The external timer supplies the 5,744 ms headline. |

**The missing compile column explains the misleading 4.95 s attribution.** `dubPhases` times compilation only between parallel-pipeline trace markers. On the recursive path it records compile as absent and charges the remaining DUB wall time to `plan`. B contains no per-package D/C split or utilization trace. Calling all 4,953 ms “platform compilation” assigns more precision than the receipt provides. [Phase accounting](../../../apps/flint/src/flint_tool/engine/builder.d:293)

**Why compilation serializes.** PetClinic’s lock lists 57 build packages. `flint:boot-core` brings in both `flint:term` and `flint:os`. On Linux, `term` runs `sh native/build.sh`, which invokes `cc` on `native/linux.c` and produces `terminal-linux.o`. `os` supplies `interrupt_latch.c` as a compiler input. The fork’s `canUseParallelPipeline` rejects the whole graph for either a pre-build command or an unhandled `.c` source. DUB therefore visits dependencies recursively, building package targets in order. The normal parallel path already splits packages into DMD jobs and archives libraries concurrently. The scratch fix is to make those two inputs schedulable. [Package lock](../../../benchmarks/spring/flint/petclinic-rest/flint.lock:50) · [Terminal recipe](../../../packages/term/dub.sdl:8) · [OS recipe](../../../packages/os/dub.sdl:7) · [DUB eligibility and scheduler](../../../toolchain/dub-1.43.0-flint.patch:206)

**What Go rebuilds.** `go build -a .` uses an empty `GOCACHE` and verified module sources already on disk. It recompiles the app’s transitive imports, including the runtime, the standard-library packages it uses, and **31 third-party packages** including pgx, pgtype and their dependencies. Unused standard-library packages are outside that graph. `CGO_ENABLED=0` means the PostgreSQL driver is compiled Go code. Independent package builds run concurrently, with default `-p` set from `GOMAXPROCS`. Venus reports **32 logical CPUs**. Both build commands inherit runner affinity. The harness sets no two-CPU build cap, and B records neither the effective cpuset/quota nor achieved core usage. The two-CPU limit belongs to HTTP serving. Flint’s configured mold default is eight threads. [Build harness](../../../tools/spring_builds.py:68) · [Build timer](../../../tools/measure_builds.py:182) · [Go build semantics](https://pkg.go.dev/cmd/go#hdr-Compile_packages_and_dependencies)

**What “scratch” actually bought.** Flint forced D package rebuilds, linked prepared native providers and shim archives, and used the installed D runtime libraries. It did real C work for the package inputs above. Repackaging libpq, OpenSSL or the framework shims into the toolchain has no corresponding compile-time saving left at B. Also, scratch removed `.flint` and the digest log but still cloned the platform-only `FLINT_CACHE`. The **42 AOT cache hits** matter under the brief’s “everything from source” rule. The unprimed log shows 57 extractions and 473 ms of AOT, versus 171 ms at B. That difference indicates the scale of the exposure, not a controlled timing delta. Preserve B as recorded. For a strict scratch claim, start with empty derived AOT state, assert zero hits, and publish the exact installed toolchain/native boundary. If the owner intends upstream C providers themselves to be rebuilt, their clean time must enter the baseline. B gives no basis for a four-second promise on that definition. [Scratch log](../../../benchmarks/spring/evidence/phase1-builds-petclinic/20261124T023031Z/builds-logs/petclinic-rest-flint-scratch-cold-0.log) · [Unprimed log](../../../benchmarks/spring/evidence/phase1-builds-petclinic/20261124T023031Z/builds-logs/petclinic-rest-flint-prime-cached.log) · [Native build boundary](../../../tools/native_build.py:704)

**A testable target is 3.75 s:** 0.10 s CLI and overhead, 0.50 s full AOT, 2.65 s DUB planning/compilation/archives and 0.50 s link. That requires about **2.30 s** out of DUB’s residual. First give the two exceptional targets their original recipes and ordering while independent D targets run concurrently. Preserve the terminal object at link, failure propagation, target flags and sanitizer instrumentation. Trace package spans, child CPU time, worker concurrency, archive and link arguments, plus DMD `compiled`/`refused` events. Include compiler-server workers outside the CLI process tree. Scratch disables the platform prelude. Any new platform semantic state reused within a trial must be built on its clock and discarded afterward. [Compile-server contract](../../../toolchain/README.md:28)

If a few jobs still dominate, trim their **reachable module closure**, including generated registrations, service providers, static constructors, templates and CTFE. A scan of application imports alone misses those roots. Keep the full public package surface and require generated-output parity and all 109 acceptance cases. Link deduplication merits a scratch-specific trace, but even eliminating the entire 536 ms link would leave Flint behind. LDC is a low-priority diagnostic: the dev profile specifies DMD, and the forked DUB pipeline requires DMD. Compare compiler alternatives only on equivalent flags, runtime ABI and full elapsed time. [Profiles](../../../policy/profiles.toml:34) · [Link deduplication evidence](../../../docs/spring/performance-playbook.md)

## 2. Greeting-service peak RSS

**B already locates the increase.** Across nine trials, median process high-water marks in decimal MB were:

| End of phase | Flint | Go |
|---|---:|---:|
| 10 s warm-up at 20k requests/s | 11.57 | 13.80 |
| 60 s at 20k requests/s, scored RSS | **19.64** | **13.85** |
| Subsequent capacity load | 19.77 | 14.19 |

The scored ratio is **1.418 (1.393–1.453)**. The roughly **8.07 MB** rise between Flint’s phase medians is the best place to look for pool growth. `load_bench.py` reads both `VmRSS` and lifetime `VmHWM`. Trimming after the peak cannot improve that trial’s score. [Raw HTTP trials](../../../benchmarks/spring/evidence/phase1-http-gs-rest/20261124T024702Z/http.json) · [RSS sampler](../../../tools/load_bench.py:128)

The fast-path A/B gave **0.999× RSS**. Its allocation probe fell from 17 allocations to **2 / 64 bytes**, and a later probe reached **1 / 16 bytes**. Even 16 bytes at 20k requests/s gives **19.2 MB of cumulative allocation in one scored minute**. Fewer bytes can delay pool exhaustion and reduce collections while eventually touching the same pages. Druntime’s `newPool` grows successive pools by `minPoolSize + incPoolSize × pool count`, subject to size bounds. The earlier census saw **1 + 4 + 7 MiB** pools with only **440 KB live** after collection. In the fixed-live-set experiment, quadrupling garbage changed collection frequency while final heap size stayed level. This explains the observations without assuming B still collects 100 times/s. B’s per-pool residency and collection rate remain unmeasured. [GC census and pool experiments](../../../docs/spring/phase1/gc.md) · [Allocation probes](../../../docs/spring/phase1/fast-path.md:126)

**A falsifiable budget is 13.0 MB**, leaving 0.85 MB below B’s Go median. Allocate **5.8 MB** to resident GC pools, **5.1 MB** to all executable and shared-library mappings combined, **1.55 MB** to fiber/thread stacks, native buffers, allocator metadata and remaining mappings, and **0.55 MB** to rings. These are simultaneous ceilings in decimal bytes. The older 21.7 MB census predates the 200-handler limit, lazy reactor tables and affinity-aware marking. Subtracting those wins again would overstate the margin. [Playbook R-19, R-20 and R-26](../../../docs/spring/performance-playbook.md)

| Lever | First one-day experiment and decision |
|---|---|
| GC pool policy | Run queued `fast-path-pools-ab`. The earlier **−4.4 MB, −2.1% throughput** result used **4 MiB fixed pools**. The **1 MiB** result was local and separate. Even a repeated 4.4 MB saving leaves **15.24 MB**. Diagnose 1 MiB alongside the queued winner. Sample pool creation, resident bytes, live bytes after GC, bytes/request, pause distribution and all runtime metrics. `heapSizeFactor` and `heapSizeLimit` already failed to control this peak. |
| Page return | At each sweep, count whole free pages and how soon each is reused. Test `MADV_DONTNEED` only on provably free pages that stay unused before the peak. Record high-water RSS, refaults and p99. Earlier steady-load pages recycled within one cycle. Assign zero savings until measured. Leave the slower soft-dirty collector opt-in. |
| Static linking and code size | Run `release-static-ab` with matched release flags. Compare resident image pages, relocations and native heap. Musl replaces both glibc and its allocator. The historical **1.75 MB** of shared libc text counts in RSS, but a static image still executes libc code. Release already uses section collection and ModuleInfo local-class trimming. Use a link map plus touched pages to find remaining removable code. |
| Fibers and native arenas | Count allocated, active and touched stack pages at 64 connections. Test lazy stack creation at the existing 200-handler capacity, preserving guards, queuing and burst behavior. On glibc separately test `M_ARENA_MAX` and a one-time trim before load. Track live connection buffers, allocator slack, contention and faults. A smaller virtual stack or a trim of live buffers earns no RSS credit. |
| Rings and Go comparison | The SQ cap of 256 already reduced two rings to about **0.55 MB**. Inspect occupancy, CQ overflow and syscall rate before resizing. For both binaries take `smaps` at readiness, warm-up and the fixed-rate rise. Go’s static, cgo-free service has growable goroutine stacks, a paced heap and a page scavenger. Its stable 13.85 MB is measured. Its component split needs the same census. [Go GC guide](https://go.dev/doc/gc-guide) |

## Ranked actions

1. **`m7-flint-cli` with `dmd-arm64`** — Restore parallel scratch compilation around `term` and `os`. Use **2.65 s** for planning, compile and archives as the first decision point.
2. **`data-access` with `proof-harness`** — Capture the fixed-rate 8 MB rise and run the pool A/B. Choose the smallest heap that retains latency, CPU and throughput.
3. **`proof-harness` with `flint-aot`** — Audit scratch inputs, record effective CPUs, and recertify from empty derived state. Preserve primary cold as its separate platform-primed comparison.
4. **`size-levers` with `m7-flint-cli` and `web-http`** — Measure musl’s net resident saving. Pursue stack or allocator changes only where the new census shows enough bytes to close the gap.
5. **`coordinator`** — Combine independently verified winners and repeat the nine-trial comparisons at one revision. Require the applicable 99% upper bounds and throughput lower bound above 1.01. If strict scratch exceeds budget or the 13 MB memory budget requires a disallowed throughput trade, keep Phase 1 open. The owner decides the native-toolchain boundary, any shipping libc change, and whether to fund further compiler or collector work.
