# Performance playbook for porting Java libraries to Flint

This is the master record of what makes ported Spring, Spring Boot and other Java code fast, small and quick to build in Flint, and of what made it slow. Every rule comes from a measured finding. Read it before porting a module, and check a finished port against the checklist at the end.

**Keeping it current.** Any commit that improves or regresses build time, binary size or runtime adds or updates an entry here in the same commit. An entry carries:
- the rule;
- the evidence: numbers, commit and how they were measured;
- what enforces it: the gate, test or budget, or "not enforced yet".

A rule that turns out wrong is corrected, not deleted, with the evidence that changed it. Certified numbers come only from proof-harness's measurement queue (`docs/spring/phase1/coordination.md`, "Measurement"); local numbers are labelled as such.

**Why this exists.** Flint's own engines are faster than Go: `bench-rest` serves 1.68× Go's throughput in about 12 MB. A faithful port of Java's design was not: the first certified gs-rest-service run had throughput at 0.75 of Go and p99 at 2.45×. Java code is written for a JIT with escape analysis and a generational collector. It allocates freely, uses reflection-shaped generics and dispatches virtually everywhere, and in D each of those habits has a price. Phase 1 found the prices one by one; this file keeps them, so later ports pay none of them.

## 1. Runtime: CPU, latency and memory

The largest costs are per-request allocation and the collector pauses it causes. On gs-rest-service at 31 allocations per request, druntime ran about 90 stop-the-world collections a second: 7–11% of wall time paused, the GC 39% of user CPU, and those pauses drove p99 (`docs/spring/phase1/gc.md`).

| R-25 | **Every module that runs per request designs a build-time direct path, with Spring's objects materialised only when something asks for them** (owner decision `7206d97d`: the AOT fast path is Flint's default execution model, the generic Spring path its fallback). | R-17 | **An engine buffer belongs to the pooled resource, not to each checkout of it.** A statement, parse or write buffer that a connection, stream or request needs is taken from its pool's free list and given back on close. The gate's `topAllocationSitesByBytes` found it. | Allocation gate (bytes budgets); engine-jdbc's buffer-reuse test |
| R-18 | **The GC heap follows the live set times druntime's growth policy, not the allocation rate.** druntime adds pools of 1, 4, then 7 MB, and grows instead of collecting while used pages are under twice those that survived the last collection. Quadrupling garbage per request changed only the collection count. | R-19 | **Size worker pools from the Spring default they stand for, not from connection slots.** Request handlers follow Tomcat's `server.tomcat.threads.max` (200 across all reactor threads, `server.flint.max-handlers`), not one preallocated fiber per connection. Requests past the limit queue on their connections, as Tomcat's executor queues them, and are never refused for want of a handler. Each fiber is a stack plus a guard mapping that the collector also scans. | web-http, the max-handlers commit: on gs-rest-service at 2 reactor threads, idle RSS went from 11.7 to 10.2 MB, peak RSS from 19.3 to 18.5 MB (4 clients × 2,000 requests) and mappings from 4,530 to 580. Local, 3 runs each, same tree with and without the change. ADR-030 §4, "Handler limit". | engine-web `handler_limit` tests: 280 requests past a one-handler limit all answer 200; normal load unchanged |
| R-20 | **Size preallocation by use, not by limits, and keep it off the GC heap.** An engine table reserved for its limits (connection slots, operations, per-fiber cells) is allocated a chunk at a time as slots are first used, in malloc'd memory. Slots are reused lowest first, so a server's working set stays in its first chunks. A chunk that can hold GC pointers is registered as a root before its first pointer is stored and unregistered only at release; a pointer-free table is never scanned. Before cutting, rank the surviving heap by site: `liveAllocationSites` (flint.arena) names what each collection marks. | `2b2c76bf`: engine-reactor's connection, operation, I/O work and FiberLocal tables. On gs-rest-service in-process (2 workers, LDC, local, 2 runs each), the GC live set went from 2,320 to 440 KB and an idle full collection from 149–158 to 104–108 µs (minimum of 200). Release server, 64 connections, 3 runs each: idle RSS 10.2 → 8.3 MB, peak 21.0–21.5 → 19.1–19.6 MB. The heap stays 12 MB under load, which is R-18's policy, so the pool settings come next. Jackson's `JsonFactory` held its 1,024-slot property-name table inline: 8,520 bytes, one 12 KB scanned block in every mapper, and the last Jackson block in gs-rest-service's live set. The table is now allocated by the first read, so a mapper that only writes keeps a 336-byte factory, and a reading app pays exactly 8 KB (two pages, a struct with no array header). | engine-reactor `fiber_local` test: objects held only by lazily allocated chunks survive forced collections, and the test fails with the chunk's `addRange` removed; `operations` chunking and slot reuse; jackson-core `json` unittest: a write leaves the name table unallocated, and two reads return the same interned name |
| R-21 | **A concurrent collector does not pay with a small live set and heavy mutation.** Marking concurrently saves only the marking of the live set, which R-20 made small. The final stop must still rescan everything written meanwhile, which at high request rates is most of the heap, and soft-dirty tracking costs one write fault per page per collection. Shrink the live set and the stop's fixed costs first. Reach for concurrency only for a large, slowly mutating heap. | `259a864d` (D3, `gc:flint-concurrent`), measured locally on gs-rest-service at 64 connections, 3 runs per arm: 137–143k rps against 179k for druntime's collector, p99 2.65–2.75 against 0.91–1.06 ms, pause per collection 1.19–1.30 ms against 0.36–0.38 ms. D1 and D3 are parked, opt-in (coordinator, 2026-11-23); gc.md §3a. | arena `gc_stress` runs under concurrent marking, and its mover test fails without the dirty-page rescan |
| R-22 | **Never build a string to compare type names, and cache by-type bean lookups once the configuration is frozen.** A by-type lookup walks every singleton's class hierarchy; canonicalising each `TypeInfo` name one character at a time made each walk allocate per bean. Canonicalise only when there is something to remove (return the name itself otherwise), and keep Spring's `allBeanNamesByType` as an immutable snapshot published whole, cleared by any registration. | petclinic-rest's allocation gate (local, private PostgreSQL): about 995 allocations per by-type lookup removed; "unknown pet" 1,158 → 163, "update owner" 2,956 → 967, "add pet to owner" 3,331 → 1,342, "list owners" 4,334 → 3,350 (framework-core wave 1). data-access's transaction-manager cache removes the per-call lookup itself. | Allocation gate; `by_type_cache_test` (frozen, invalidation, 8 threads) |
| R-26 | **Size the collector's parallel marking from the CPUs the process may use, not the machine's.** druntime starts `parallel` scan threads up to the host's hardware threads minus one and ignores CPU affinity, so a server pinned to two CPUs of a 32-thread host marks with 31 threads competing for two, and the marking thread waits on them. A Boot application defaults to one mark thread per allowed CPU minus the collecting thread's own (`flint.arena.mark_threads`, a C constructor that puts `gcopt=parallel:<CPUs - 1>` first in `rt_options` before druntime reads it). The program's own `rt_options` and `--DRT-gcopt` still override it. Only this setting changed: pools, a startup collection and musl stay separate experiments. | `gc-pools-ab` (certified, `ce87168d`, FLINT_CORES=2, druntime's collector): `parallel:1` against the default, throughput 1.005, p99 0.809, CPU per request 0.896, max pause 13.5 → 4.0 ms. Locally (LDC and DMD): pinned to CPUs 0,1 the process starts 1 scan thread instead of 31; pinned to one CPU, none instead of 31; unpinned, 31 as before. | arena `mark_threads` test (`rt_options` order, `config.parallel` applied before `main`, the affinity count on Linux); the three apps' acceptance |

## 4. Measuring honestly

| ID | Rule | Evidence |

## 5. Correctness traps found while optimising

Speed work introduced these, or exposed them. Check every optimisation against them.

- **Shared or recycled objects across reactor threads.** Immutability, or a loud failure on misuse, plus a concurrent test (R-4, R-6).
- **No ThreadSanitizer lane yet: druntime's collector blocks it.** LDC's `-fsanitize=thread` builds the framework tests, but the run never finishes. After 10 minutes on 32 CPUs the binary was still spinning in the stop-the-world collector, with no report (web-http, `351683be`). Until the collector cooperates with TSan (D3's concern), use concurrent tests whose failure is visible, checked against a planted fault: `concurrent_dispatch_tests` fails when a per-call field is planted on the shared invocable.
- **Thread-local storage in shared libraries.** The AArch64 backend used local-exec TLS under `-fPIC`, so a library's variables silently aliased the executable's. Initial-exec through the GOT is used now, with tests that cover `dlopen`.
- **Signal dispositions inherited by worker processes.** An ignored `SIGCHLD` turned linker failures into success (`027721b6`).
- **Caches and replays that go stale silently.** Test that adding a file, removing one, changing a string import, or restoring an mtime invalidates them (`87c13a93`, `c4a5a8b2`).
- **`typeid` of an interface reference names the interface,** not the object's class. Exact-class checks use `typeid(cast(Object) x)`. The fast path's startup proof silently declined every route until this was fixed, which only the allocation counter showed (fast-path.md §8.1).
- **A nested function's address stored in a field of a non-`scope` local struct makes D allocate a GC closure** of the whole frame, stack buffers included: 2 allocations and about 4 KB per request in the fast-path prototype. Declare the struct `scope`, and check with `-vgc` (fast-path.md §8.2).
- **Pay-for-use registration gaps.** Every typed path that can need the optional code must link it. The remaining gap is a recorded deviation with a loud message (D-JACKSON-10).

## 6. Checklist for porting a module

Before a ported module lands:

1. **Allocations.** Count GC allocations per call on its hot paths with the counting method in gc.md. Only user-visible objects may remain (R-1 to R-8). Add or lower its entry in `policy/request-allocations.json` once the gate exists.
2. **Hot-path engine code** is `nothrow @nogc`, returns `Result`, and uses the arena or reused buffers.
3. **No per-call parsing** of anything that could be parsed once and cached (R-2); no monitors on lookups (R-7).
4. **Templates.** Generic public APIs are thin façades over erased engines (B-1). No heavyweight Phobos templates (B-2). The module stays within its template budget.
5. **Size.** Linked bytes stay within the module's ratio and ceiling. Optional functionality is unreachable unless used (S-1). No `std.process`, `std.file` or `std.path` (S-2).
6. **Exceptions** used for control flow skip backtraces (R-11).
7. **Shared state.** Anything created once and shared is immutable after warm-up, or protected, and has a concurrent test (R-4).
8. **Generated code.** Anything the module asks Flint AOT to generate instantiates nothing per type it can look up (B-3).
9. **Records.** New findings are added to this file in the same commit.
