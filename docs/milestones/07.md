# Milestone 07 · The `flint` CLI core and the project model

Branch `m7-flint-cli`, cut from `codex/flint-milestones` at `31bd297` (ADR-021). Built and verified on `venus` (Ubuntu 24.04, x86-64, 32 hardware threads) with the pinned forked DMD 2.114.0, forked DUB 1.43.0 and LDC 1.43.0. Decisions and public API additions are recorded in [ADR-022](../adr/ADR-022-milestone-7-decisions.md). The command reference is [docs/flint-cli.md](../flint-cli.md).

## What was built

- **The `flint` executable.** It lives in [`apps/flint`](../../apps/flint), laid out as ADR-021 section 2 prescribes. It is written in D on `cli`, `config`, `log`, `os`, `term`, `serde` and `test`, about 8,300 lines of source and 650 lines of unit tests in 34 modules. The 37-package surface is unchanged.
- **Commands.** `new`, `build`, `run`, `test`, `check`, `fmt`, `lock`, `toolchain install|verify|info`, `doctor`, `daemon start|stop|status`, `version`, `explain` and `receipt`. Every command has `--json` output (one versioned schema per command), uses the stable exit codes 0–4 and never prompts.
- **The project model.**
  - `flint.toml` has a closed schema with located, did-you-mean diagnostics.
  - Dependencies: Flint core packages (versioned by the platform), path dependencies (Flint library projects or local DUB packages) and test dependencies.
  - `flint.lock` is deterministic and byte-verified, with content, toolchain and policy hashes.
  - Checked conventions: `config/application*.toml`, `src/<root>/` and `test/<root>/`, module paths matching file paths. `.flint/` holds the generated DUB recipe, builds, receipts and DUB cache.
  - `flint new` creates a project that builds, runs and tests. `--starter` scaffolds the starter's core packages.
- **Profiles as data.** `policy/profiles.toml` is read by `flint` through `flint.config` and by `tools/ci.py` and `tools/measure_builds.py` through `tools/profiles.py`, with byte-identical flags. `policy/platform.toml` holds the platform version.
- **Receipts.** Every artifact gets a `flint.receipt/1` receipt. Added flags, a non-profile compiler or an unverified toolchain mark it non-canonical. `flint toolchain install` writes the toolchain receipt that ties the installed fork to `toolchain/*.patch`.
- **Safety in the build.** The structural gate's rules (`tools/gates.py`), the dfmt and D-Scanner checks (`tools/quality.py`) and `policy/safety-policy.json` are ported to D and shared by workspace and project checks. `flint build` and `flint test` run the fast subset. `flint check` runs everything, including the DMD `-deps`/`-mixin` audit in the workspace.
- **Diagnostics v1.** 83 catalogued `FLINT-Ennnn` codes, each with a cause, fix, location and snippet, a JSON form and `flint explain`.
- **Dogfooding.** The workspace's packages build and test through `flint`. `tools/install_toolchains.py --compiler flint` bootstraps `flint` with DUB; `flint` then rebuilds itself and verifies its own receipt.

Library gaps closed in the libraries:

- `flint.config`: `ConfigOptions.baseName` and `readEnvironment`.
- `flint.serde.owned.serialize`.
- `flint.term.describe`.
- `flint:os`: its ImportC interrupt latch failed to link in every DMD library build.
- `flint:term`: its C shim failed to compile under Ubuntu's fortified GCC.

- `flint test` gives `desktop` the per-package environment `tools/ci.py` gives it. With no display, its suite runs on SDL's offscreen driver (ADR-020). Without that environment, `desktop`'s SDL runtime test failed on venus, which has no display.
- The one failing run was `flint:log` on LDC (`tests/concurrency.d:186`). That intermittent failure predates Milestone 7 and is now fixed in the test:
  - **Cause.** Each producer thread has its own ring, and the single consumer drains the rings in turn. The worker thread's records could therefore be delivered between the main thread's fiber records. The spec guarantees per-producer order and monotonic delivery sequence IDs, not one global submission order, so the test asserted more than the spec promises.
  - **Fix.** The test now checks each thread's records in submission order and strictly increasing sequence IDs.
  - **Before.** With 32 runs in parallel, the test failed 30 to 58 times in 400 runs.
  - **After.** 0 failures in 400 runs under the same contention, in 100 consecutive LDC `dub test :log` runs and in 20 consecutive DMD runs.

### Fixture peers and a canonical toolchain on venus

- **Toolchain receipt.** `flint toolchain install` ran on venus after the fiber-wake session finished benchmarking. It rebuilt the fork with PGO and recorded `.tools/flint-toolchain.json`, taking 3 min 15 s, exit 0. It first stopped the one compile server still running the old `dmd`. `flint toolchain verify` now exits 0, `flint doctor` reports the fork's receipt verified, and venus builds are canonical. The first attempt, in an earlier build of `flint`, exposed two defects that were then fixed:
  - `install_quality_tools.py` ran without the pinned toolchain on `PATH`;
  - a running compile server made the installer's extraction fail with "Text file busy".
- **Pinned peer binaries.** `python3 tools/install_peers.py --peer go --peer postgres` installed Go 1.27.4 from `policy/toolchains.json` and built PostgreSQL 18.7 from the pinned libpq source, in 26 s, exit 0.
- **Peer-dependent suites against their peers:** `ai`, `http`, `security`, `mail`, `sql`, `data` and `migrate` passed both offline and with peers.
  - Against a closed PostgreSQL port the `sql` binary fails, so the PostgreSQL tests really run.
  - The AI peer verified its 30 requests.
- **Missing peers:** `storage` (MinIO) and `cache` (Valkey) fail with FLINT-E0815, because neither has a pinned release in the repository. Their offline tests and `storage`'s S3 peer pass.
- **All 37 packages with peers:** `flint test --compiler both` took 1 min 44 s and exited 2. 70 of 74 runs passed, 16 of them also against their peers. The four failures are `cache` and `storage` on each compiler, failed with FLINT-E0815 for the unpinned Valkey and MinIO. Every suite that ran passed.
- **`tools/ci.py`.** It never started peers. The peers were previously run by hand with each package's own runner from its `ACCEPTANCE.md`, and `flint test` now runs those same runners.

Before the providers were built, `flint doctor` reported their absence as FLINT-E0808, and native-linked packages failed with FLINT-E0701 and the linker's own message.

### Toolchain and canonical builds

- On venus, `flint toolchain verify` exits 2 with FLINT-E0804. The shared `.tools` fork predates the toolchain receipt, so its provenance cannot be shown, and venus builds are reported as non-canonical. Running `flint toolchain install` there rebuilds the fork in place and records the receipt.
- `flint toolchain install --toolchain-dir <scratch> --no-pgo` installed the fork from the pinned archives in 2 min 41 s (exit 0) and wrote `flint-toolchain.json`. With that toolchain (`FLINT_TOOLCHAIN_DIR`), `flint toolchain verify` exits 0, and `flint build --verify` and `flint build --profile release --verify` produce canonical receipts that `flint receipt --canonical` accepts (exit 0).
- Appending one byte to the release artifact makes `flint receipt` fail with FLINT-E0902 (exit 2). Rebuilding with `--dflags=-mcpu=native` makes `flint receipt --canonical` refuse it with FLINT-E0904 (exit 2).

## Deviations and decisions to review

- `flint` does not link `style`, which needs utf8proc and a C shim, so `flint` can still bootstrap without native providers (ADR-022 decision 2).
- The lock of a project inside the Flint checkout is pinned by the workspace commit instead of content hashes (ADR-022 decision 7).
- `tools/measure_builds.py`'s protocol digest changes with the move of its flags to policy. The flags are identical (ADR-022, measurement method changes).
- Workspace receipts are written to `.flint/receipts/` because the workspace artifacts live inside `packages/`.
- `tools/quality.py` skips any directory named `build`, so the CLI's build engine lives in `src/flint_tool/engine/`. Project checks skip only `.flint/` and `.dub/`, so a project's own `build/` source directory is still checked.
