# Milestone 06 · Linux certification

Certified commit `d076103516593ea6a454374c28cec7362129868e` on branch `codex/flint-milestones`.

The initial baseline gate (`tools/gates.py --gate baseline`) passes every condition except cross-platform validation. That one fails by design: ADR-017 decision 2 keeps macOS arm64 and Windows x86-64 in Gate 6 as visibly incomplete targets rather than removing them. Every Linux target in scope, x86-64 and AArch64 with glibc and static musl, passed, and so did wasm32. No regression comparison ran because this is the first recorded baseline (`handoff/docs/CI_PERFORMANCE_BUDGETS.md`). The evidence at `d076103` becomes the protected base for later comparisons.

```text
$ python3 tools/gates.py --gate baseline --evidence current.json
GATE FAILED: missing/failing cross-platform validation
```

With the platform condition removed, the same evidence passes artifact verification and every measured condition. That includes all 37 packages' absolute caps and every Go comparison.

## Decisions this milestone rests on

- [ADR-016](../adr/ADR-016-resident-toolchain-compile-server.md) counts the forked DMD's resident compile server, which holds only druntime and Phobos, as a retained toolchain runtime, the way Go keeps its standard library compiled. Cold trials may start with the server running. This report states the first build without a server (below).
- [ADR-017](../adr/ADR-017-milestone-6-decisions.md) records the owner's fourteen decisions:
  - the non-ephemeral runner;
  - the platform scope;
  - Sigstore signing;
  - GitHub Actions disabled;
  - behaviour fixes;
  - PR to `main`;
  - the REST size guardrail at 0.99 of Go.

  It also lists five measurement-method changes, each explained there with before and after numbers.
- [ADR-019](../adr/ADR-019-package-template-budget.md) counts a package's template budget over its own library and probe compiles. The closure count it replaces is still recorded, shown in parentheses in the package table. At `d076103` the two counts are equal for every package.
- [ADR-020](../adr/ADR-020-desktop-webview-shell.md) rebuilds `flint:desktop` on Tauri v2's architecture in D over GTK and WebKitGTK, with no Rust.
- [ADR-018](../adr/ADR-018-flint-cli.md) defines the `flint` CLI, which is Milestone 7.

## Runner and conditions

All evidence comes from `flint-perf-x86_64-v1`, the project workstation:

- **Machine:** AMD Ryzen 9 5900X (family 25, model 33, microcode `0xa20102e`), NixOS, Linux 6.18.59, glibc 2.44.
- **Governor:** `performance` on every CPU.
- **CPU placement:** server benchmarks use CPUs 2–3 and the load generator CPUs 4–7, with their SMT siblings idle.
- **Fingerprints:**
  - runner `0a9138d6…ae15`;
  - toolchain `f0b50bfc…71fb`;
  - native lock `ee4646ff…cc8e`;
  - workload `321c2f95…d400`.

The runner is **not ephemeral**, and the evidence records `runner_ephemeral: false` as ADR-017 decision 1 requires. It is a long-lived desktop. During every official run, three unrelated user processes each held one core at 100%: `owe-render`, a worker thread of a defunct `filmcraft-cli`, and `Xwayland`. The desktop session also stayed active. Before the final run, stopping the first two was attempted. Both have SIGKILL pending but keep running inside the kernel, so only a reboot clears them, and the run went ahead with them. This is interference that a dedicated runner would not have, and it acts against Flint's parallel builds, which use every hardware thread, more than against Go's.

Toolchains:

- the forked DMD 2.114.0 with the resident compile server;
- the forked DUB 1.43.0 with the parallel byte-cost pipeline;
- direct `mold` linking;
- LDC 1.43.0 for release builds;
- Clang/LLVM 22.1.8 for sanitizers;
- Go 1.27.4 as the comparator.

The four failures at `96e475e`:

- **Test package link size, 661 KB against a 262 KB cap.** The test runner's `std.stdio` and `std.random` pulled a static-Phobos archive cascade (variant → curl, concurrency, datetime).
- **Prompt link size, 525 KB.** `std.utf` and `std.conv` caused the same cascade.
- **Mail templates, 7,928 against a 2,000 cap.** Its probe parsed a two-field record with `std.json`.
- **bench-cli build ratio, upper bound 1.449.** Compile-server start-up overlapped trials 1 and 2. The server is now primed before the trials, as ADR-016 specifies (ADR-017 method change 3).

None of these fixes changed a public API or the D language. The runner, prompt and probe changes keep their behaviour and are covered by new tests.

## Linux AArch64

Both AArch64 lanes ran at `d076103` in a full-system QEMU 11.1.2 ARM64 guest, not on ARM hardware:
- **Emulation:** TCG, `-cpu max -smp 4`.
- **Kernel:** Alpine Linux 6.12.118.
- **Toolchain:** the pinned AArch64 LDC 1.43.0.

Each lane's driver checks the `git archive` export against the commit and rehashes the 19 reused provider builds, whose lock rows are unchanged. It rebuilds the Flint C shims and relinks all 37 test executables. Then it runs everything in one VM:
- all 37 suites;
- the four native C checks (ABI probe, llhttp/zlib, real io_uring, setup-denied seccomp) and the MQ socket check;
- the independent peers:
  - HTTP with TLS and HTTP/2, and SMTP;
  - Web, Storage and AI;
  - Valkey;
  - Kafka and JetStream, plain and over TLS;
  - PostgreSQL 18.6 UTF8.

The driver exits 0 only if every step passed. `tools/collect_evidence.py record` wrapped it directly, so the Gate 6 receipt is the run itself.

| Lane | Suites | Modules | Native checks | Peers | Receipt exit | Time |
| --- | ---: | ---: | --- | --- | ---: | ---: |
| linux-aarch64-glibc | 37/37 | 289 | pass | pass | 0 | 457 s |
| linux-aarch64-musl (static) | 37/37 | 289 | pass | pass | 0 | 335 s |

Every musl executable is static, with no interpreter or dynamic section. Every glibc executable needs only `/lib/ld-linux-aarch64.so.1` and standard glibc libraries. At `0a94039`, whose code is identical, the cache suite passed 200 consecutive runs and SQL 10 in each guest; at `44e078f`, SQL passed 30 consecutive runs in the musl guest.

The lane runs with three settings, stated in each lane README:
- `FLINT_EMULATED=1`, explained below;
- a static AArch64 `curl` on the guest `PATH`, for Web's HTTP/2 upgrade test;
- a 600 s per-check limit. Config's exhaustive UTF-8 check takes 188 s under emulation.

Under `FLINT_EMULATED=1`, wall-clock bounds are reported instead of asserted (ADR-017 method change 5). These bounds were reported as not met at `0a94039`, against measured plain-C baselines of about 4.5–5 ms for `fork`/`exec`/`wait` and 0.5–0.7 ms for a loopback round trip in the same guest:

| Bound (glibc lane) | Measured |
| --- | ---: |
| Web echo, 200 rounds (100 ms) | 273 ms |
| HTTP exchange (1 ms) | 2.59 ms |
| SQL handoffs, 400 (100 ms) | 226 ms |
| OS reaping median (3 ms) | 10.9 ms |

Every functional assertion in those tests ran and passed. ARM performance has not been measured on hardware.

**Static applications.** The canonical apps were built O3 and Oz as static AArch64 musl binaries. The build was from `0a94039`, whose code equals `d076103`. In the guest, each CLI printed `Hello, Flint!` and the expected log, and each REST server passed 11 loopback checks.

| --- | ---: | ---: | ---: |
| bench-cli | 1,085,216 | 1,064,880 | 3,000,000 |
| bench-rest | 6,120,568 | 6,100,296 | 8,000,000 |

**What the replays found.** The first replay at `00ea4fc` passed 31/37 suites on glibc and 32/37 on musl. Most failures were wall-clock bounds measuring the emulator, but the replays also found three test defects, fixed rather than relaxed:

1. **`d3e5bef`:** the conc cancellation-order check had a 1 µs deadline margin. Separately, SQL `pool_saturation` hung `close` after a failed check and raced its probe against waiters re-queuing.
2. **`5e92b0f`:** that test's must-reject probes had a 1 ms deadline, which a starved thread could pass before `acquire` reached the queue.
3. **`44e078f`:** the test assumed no queued wait would reach the specification's min(deadline, 5 s) bound. An interim attempt at `7534abb` raised the bound in the test, but the pool clamps it, so that had no effect.

The x86-64 lanes at `44e078f` then found a library crash (see run history), fixed in `0a94039`, and both AArch64 lanes were recorded again there. The first musl recording at `0a94039` failed when the replay harness's own JetStream container step raced Docker's removal of the previous container; the lane was re-recorded with a separate container name for each mode, and the failed receipt is kept with the evidence. `d076103` then moved two SAFETY comments that the structural gate rejected, and both lanes were recorded once more. Every superseded recording is kept beside the final one.
