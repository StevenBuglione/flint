# Milestone 08 · Dependencies and packaging

Built on `main` (rebased onto `2949191` and later `c5be651`, each checkpoint pushed straight to `main`) and verified on `venus` (Ubuntu 24.04, x86-64) with the pinned forked DMD 2.114.0, forked DUB 1.43.0, LDC 1.43.0, clang 22.1.8 and Conan 2.34.0. It implements the Milestone 8 row of [ADR-021](../adr/ADR-021-flint-platform.md): section 4, with the parts of sections 1, 5 and 9 it needs. Decisions and API additions are in [ADR-023](../adr/ADR-023-milestone-8-decisions.md). The command reference is [docs/flint-cli.md](../flint-cli.md).

## What was built

- **Go-style dependencies.** Repository paths take a minimum release version (`"github.com/acme/money" = "1.2.0"`). Versions are chosen by minimal version selection over tags.
  - **Fetching:** through git bare mirrors into a content-addressed cache under the Flint home, with `FLINT_PROXY`, `FLINT_CACHE` and `FLINT_OFFLINE`.
  - **The lock:** `flint.lock` records each module's version, tag commit and tree hash, and every use re-verifies the tree.
  - **Commands:** `flint deps tree`, `why`, `update` and `vendor`. With a vendored copy, `vendor/` becomes the build list.
- **Native packages with Conan hidden inside.**
  - **The engine:** `flint toolchain install` installs a pinned, checksum-verified, self-contained Conan 2.34.0. It runs only with an isolated home whose single remote is Flint's checked-in recipe index, `native/conan-index`.
  - **The index:** a Conan `local-recipes-index` generated from `policy/native-lock.json` for the 19 providers. Each recipe has the same sources and hashes, licences, dependencies and targets as the lock, builds through `tools/native_build.py`'s vetted per-library steps, and pins those steps' SHA-256.
  - **The resolver:** `tools/native_resolver.py` drives Conan and answers in JSON, in Flint's words. Conan's output stays in a log.
  - **In a project:** `[native]` gives `flint.lock` entries with recipe revision, package ID, source hash and binary hash, checked on every build. Two versions of one package are FLINT-E0320, which names both requesters.
  - **Linkage:** `system = true` uses the host's library and marks the build non-portable. `bundled` ships a shared library in `lib/` with an `$ORIGIN/../lib` run path.
  - **musl:** native packages cross-build for musl with a generated CMake toolchain file.
- **Embedded C** in `native/` or `[native.c]`.
  - **Compiling:** the pinned clang compiles C11 or C17 with `-Wall -Wextra -Werror`, `_FORTIFY_SOURCE=3`, the stack protector, stack-clash protection, `-ftrivial-auto-var-init=zero` and PIE. Executables link with RELRO and BIND_NOW. All of this is fixed by `policy/native-c.toml`.
  - **Caching:** objects are cached by the hash of compiler, flags and preprocessed unit.
  - **Checks:** `flint check` runs clang-tidy's fixed profile, and `flint test --sanitize` builds the C, the D and the native packages with ASan and UBSan.
  - **The ffi boundary:** FLINT-E0513 confines `extern(C)` and ImportC files to `<root>.ffi` modules.
- **`flint package [--target T] [--container] [--sbom]`.**
  - **The build:** a stripped release build, static by default and verified from its ELF headers, staged with `config/` and `resources/` and archived reproducibly.
  - **musl:** `linux-x86_64-musl` is a static PIE cross-linked on the glibc host against a musl sysroot that flint assembles from six checksum-pinned Alpine packages.
  - **`--container`:** writes a `FROM scratch` OCI image without a container engine.
  - **`--sbom`:** writes SPDX 2.3 and CycloneDX 1.6.
  - **Reproducible:** with `SOURCE_DATE_EPOCH`, every output is byte-identical across rebuilds.
  - **`flint deps audit`:** verifies the lock and every module, DUB and native hash, lists licences, and states the LGPL and AGPL obligations.
- **DUB compatibility index.** `"dub:<name>" = "<version>"` resolves through `policy/dub-index.toml`, which pins repository, commit, tree hash, licence, DUB dependencies and native recipes. It is seeded with D-YAML 0.10.0 and tinyendian 0.2.0.
  - **The safety rules:** Flint runs its safety rules over every DUB package.
  - **Waivers:** a package that fails them needs an `[unchecked]` waiver with a reason. The waiver is printed on every build and recorded in the receipt, both SBOMs and the audit.
  - **Building:** DUB builds a disposable working copy, so the cache and user checkouts are never written.
- **Diagnostics.** The catalogue grows from 83 to 106 codes. flint is about 13,500 lines of D in 51 modules, with 12 unit-test modules.

### Toolchain added

Everything below is pinned in `policy/toolchains.json`. Nothing was installed with apt.

- **Conan:** `conan-2.34.0-linux-x86_64.tgz`, SHA-256 `655177bf…27b6`, matching GitHub's release asset digest.
- **musl sysroot:** six Alpine 3.22 packages (musl and musl-dev 1.2.5-r13, gcc and libgcc 14.2.0-r6, linux-headers 6.14.2-r0, libunwind-static 1.8.1-r0), each with a SHA-256.
- **Alpine LDC:** `ldc2-1.43.0-alpine-x86_64` from the existing pins.
- **LLVM:** the pinned release now also provides `clang-tidy`.

## Fixed along the way

- An empty manifest table, such as the bare `[dependencies]` that `flint new --type library` writes, was rejected. Nested path dependencies got wrong relative recipe paths.
- `flint daemon stop` could return before the server's lock holder exited. The stale socket it left made `test_version_doctor_and_daemon_report_json` fail in about half of all runs; it now passed 10 of 10.
- `FixturePeerTests` asserted on `diagnostics[0]`, which a host without a toolchain receipt fills with an E0804 warning. The tests now find their diagnostic by code; this was verified against a simulated receipt-less toolchain.

## Host findings from the performance runner

- **Paths with spaces.** A project and a toolchain both under paths with spaces now build, test (with sanitizers too), check and package for musl with a container.
  - The musl target's `ldc2.conf`, the only path flint passes through `DFLAGS`, which DUB splits at whitespace, moves to a content-addressed temporary file when the project path has spaces.
  - `flint doctor` reports a pre-`c5be651` `dmd.conf` that would split its own paths (FLINT-E0821).
- **DUB's libcurl.** `flint doctor` checks that DUB can load libcurl and gives the fix, with a NixOS `LD_LIBRARY_PATH` command (FLINT-E0820). `flint toolchain install` checks this up front, the quality-tool installer exits with a plain message, and installer errors go to a log with a one-line summary instead of a traceback.

## Limits and follow-ups

- **Native binaries for other targets.** They build from source; there is no signed binary remote yet (ADR-021's Sigstore-signed Flint remote). On a glibc host, musl native packages cross-build only for CMake providers. The others, such as OpenSSL, need a musl runner, as before.
- **`bundled`** is a shared library produced from the package's position-independent static archives, not an upstream shared build.
- **The DUB index** holds two packages. Growing it is curation work, and almost every existing DUB package will need an `[unchecked]` waiver because none declares `@safe:` defaults.
- **`flint deps audit`** checks hashes and licences, but not known vulnerabilities, which ADR-021 also lists.
- **Retiring `native_build.py`.** It stays the workspace's default native path until this equivalence is accepted. Its build steps already back the recipes.
