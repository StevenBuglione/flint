# Milestone 09 · Knowledge, diagnostics and tooling

Milestone 9 was built on `main`, with each checkpoint pushed straight to `main`: 025e927, 090af63, 1ddc741, 9e8f6be, 2829f58 and efcef92. It was verified on `venus` (Ubuntu 24.04, x86-64) with the pinned forked DMD 2.114.0, forked DUB 1.43.0 and LDC 1.43.0.

It implements the Milestone 9 row of [ADR-021](../adr/ADR-021-flint-platform.md): sections 6, 7 and 11, and the tooling parts of section 1. Decisions and API additions are recorded in [ADR-027](../adr/ADR-027-milestone-9-decisions.md). The command reference is [docs/flint-cli.md](../flint-cli.md).

## What was built

### Knowledge

- **The API index.** It is built from the pinned compiler's JSON output for all 37 packages, and the commands below answer from it offline:
  - `flint docs` searches signatures and documentation, and `--export` writes `llms.txt`;
  - `flint examples` shows the tested unittest blocks that use a symbol;
  - `flint explain` gives the long form of every diagnostic.
- **`flint generate`** writes canonical components: entity, repository, service, controller, config, migration and debug configurations.
- **New projects** get a generated `AGENTS.md`.

### `flint mcp`

- **The server.** `flint mcp` is built on `flint:mcp`, which gains blocking tools, and serves the section 6 tools over stdio:
  - `search_api`, `get_symbol`, `get_example` and `explain_error`;
  - `describe_project`, `resolved_config` and `dependency_graph`;
  - `generate`, `build`, `test` and `check`.
- **The call log.** `--log` keeps a call log, which the vibe-coding benchmark scores.

### The fast feedback loop

- **`flint watch`** rebuilds and restarts, or retests, once per change.
- **Debugging.** `flint run --debug` launches gdb or lldb with Flint pretty-printers, and the generated launch configurations do the same in an editor.

### `flint lsp`

- **Diagnostics** come from the pinned compiler, including unsaved buffers, and from Flint's policy rules.
- **Hover, go-to-definition and completion** answer from the API index.
- **The compile server** was measured with the editor's own workload and not adopted. ADR-027 section 4 proposes the change to ADR-016 that would make it pay.

### Diagnostics v2

- **One error per misuse.** Every framework misuse in `tests/compile/misuse` is one error at the user's line, naming the field, handler or service.
- **In the libraries:** checks in serde, config and web now name the field, handler or service.
- **In the DMD fork:** the new `-verror-hide` re-anchors errors raised inside library code, collapses the hidden frames and rewrites library `static assert` messages. Object output stays byte-identical.

### The vibe-coding benchmark

- **The tasks:** four (`rest-notes`, `cli-todo`, `queue-worker`, `tui-dashboard`), each with a black-box acceptance test.
- **The harness:** `tools/vibe_bench.py` runs Claude Code, Codex or any agent command and scores success, build–fix iterations, wall time and review size.
- **Reference and oracles:** a Flint reference for `cli-todo`, and Python oracles that prove the other acceptance tests sound.

### Library additions found by the benchmark

- **flint:config** binds keys relaxed, as Spring Boot does.
- **flint:cli** prints help for subcommands.
- **flint:term** gains `writeStream`, which writes to standard error from `@safe` code.

### Size

The diagnostics catalogue has 111 codes. flint is about 17,400 lines of D in `apps/flint/src`.

## Limits and follow-ups

- **Rebuilding the shared fork.** The shared toolchain in `.tools` still runs the previous fork.
  - **What it reports:** builds warn FLINT-E0805 and do not pass `-verror-hide`.
  - **The failing tests:** the fork half of `tests/test_flint_diagnostics.py` fails until `flint toolchain install` rebuilds it.
  - **Other projects:** projects outside the workspace need `flint lock` after the rebuild.
  - **Who does it:** the rebuild of the shared toolchain is left to its owner.
- **Flint references** for `rest-notes`, `queue-worker` and `tui-dashboard` are still to be written, as are the Go and Spring Boot references. Writing them is how the remaining library gaps will be found.
- **Agent runs.** No agent run has happened yet. A run needs a signed-in `claude` or `codex` CLI, a budget of at least 36 runs for the full matrix, and a pinned `--model` (`benchmarks/vibe/README.md`).
- **lldb printers.** `tools/debug/flint_lldb.py` is untested; gdb is tested.
